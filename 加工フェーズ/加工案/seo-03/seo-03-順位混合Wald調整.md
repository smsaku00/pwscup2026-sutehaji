# seo-03：順位混合Wald調整

## ①基本情報

- 作成者：**seo**
- 案番号：**seo-03**
- 方式名：**順位混合Wald調整**
- 対象：PWS Cup 2026 本選・加工フェーズ（main-process-20260912）
- 実行ファイル：`seo-03-順位混合Wald調整.py`
- 出力ファイル：`C_seo-03-順位混合Wald調整.csv`

この案は、seo-01で確認した「3人の順位混合」を数値属性に使い、生存時間と発症の関係に **Wald z値の追加調整**を1回加えた方式です。seo-01と同じレコード混合強度を保ちつつ、Cox回帰の係数だけでなく標準誤差も近づけることが目的です。

## ②ルールとの対応

参照した文書は `PWS_Cup2026_ルールブック_main-process-20260912.pdf` です。

- 出力はルールブック§5.1の `C.csv` 仕様に合わせ、1049行×13列で作成しました。
- 年齢、検査値、`time`、0/1列、発症と死亡の排他などの公開スキーマをコード内で検査します。
- 公開希少検出器の定数は `participant_data/schema.json` と同じ値で固定しています。個人の希少正解ラベルは使いません。
- ジェネレータが読む個票データは、実行時に指定した `B.csv` と `A_bg.csv` だけです。`B_self`、攻撃challenge、真値、他チームC、過去のCは読みません。
- `A_bg.csv` はインターフェースと入力形式の検査にのみ使い、合成値の計算には使いません。
- データとコードの取扱いは§3.2、監査可能性とAI利用は§7.4–7.5を前提としています。

## ③概要と狙い

個人の1行を少しだけ動かすだけでは、元データBの近くにCの行が残り、最近傍型MIAに利用される可能性があります。逆に、値を大きく乱すと有用性が落ちます。

そこで本案は、数値属性を順位に変えてから3人分を混ぜ、各列の元の分布に戻します。これにより、「各1行の属性の組合せ」は変わりますが、「列ごとの分布」はほぼ維持されます。

さらに、`time/onset/death` は危険度帯の中で割り当て直し、Cox回帰の係数を調整した後、Wald z値（係数÷標準誤差）もBに近づけます。

## ④加工手順

1. `B.csv` と `A_bg.csv` の列、型、欠測、値域、結果列の整合性を検査します。
2. 数値7属性（age, BMI, SBP, TG, HDL, ALT, FPG）を列ごとに順位化し、標準正規分布の座標に変換します。
3. 公開検出器で一般群と検出希少群に分けます。
4. 各群内で独立に3回並べ替えた行を取り、標準正規座標を `(行1+行2+行3)/√3` で混合します。
5. 混合後の順位に従って、Bの各列の値を割り当て直します。検査値にはIQRの1.2% scaleの小さなノイズを加え、公開値域に収めます。
6. `sex/smoking/prefecture` は、数値属性が最も整合する一対一割当て（Hungarian assignment）で付け直します。
7. BのCox危険度とC候補のCox危険度を64帯に分け、同じ帯の中で `time/onset/death` の3つ組を再配置します。
8. イベント時間には標準0.015年の小さなノイズを加えます。非発症・非死亡はBの打切り時間の中央値に統一します。
9. 30,000回の入替えでCox係数の勾配損失を下げます。
10. Cを再度Cox回帰し、BとCの標準誤差比を0.8–1.2に制限して、Wald z値を近づける追加調整を1回行います。
11. 最後に行順をシャッフルし、保存後に同じ数値を読み戻せることを確認します。

## ⑤パラメータ

| 項目 | 固定値 | 意味 |
|---|---:|---|
| 乱数seed | 9203 | 提出用の既定値 |
| 混合人数 | 3 | 1行の数値パターンを3人から合成 |
| 検査値ノイズ | IQR×0.012 | 完全一致を減らす小撾乱 |
| 危険度帯 | 64 | 結果列の再配置粒度 |
| イベント時間ノイズ | 標準0.015年 | 発症・死亡時間の小撾乱 |
| Cox入替え | 30,000回×2段階 | 係数調整＋Wald調整 |
| Wald標準誤差比 | 0.8–1.2 | 過大な修正を防ぐ制限 |

## ⑥適用条件

- BとA_bgがそれぞれ30行以上であること。
- Bの `onset=1` が10行以上あり、Cox回帰が数値的に退化しないこと。
- 一般群・公開検出希少群のうち、存在する群は3人以上であること。
- 公開スキーマの13列と値域に合うこと。
- Python 3.12、NumPy、pandas、SciPy、lifelinesが必要です。

## ⑦開発履歴

1. 最初に、3行の平均と散らばりを保つ直交回転を試しました。しかし、強く混ぜると希少有用性が0.61–0.86に下がり、弱くすると最近傍MIA診断が悪化したため採用しませんでした。
2. 2–5人の参照数を変える案も試しましたが、本開発Bでは希少有用性が0.65–0.70程度まで落ちたため採用しませんでした。
3. 数値属性は検証済みの3人混合に戻し、結果列の調整だけにWald第2段階を加えました。
4. 64帯・0.015年ノイズ・Wald 1回を最終設定とし、その後に攻撃診断を実施しました。攻撃真値は生成器の候補選択に戻していません。

## ⑧実行方法

`seo-03-順位混合Wald調整.py` を任意のフォルダに置き、次のように実行します。

```powershell
python "seo-03-順位混合Wald調整.py" --b "B.csv" --a-bg "A_bg.csv"
```

## ⑪弱点と次の検証

- **seed依存性**：別seed 20260921ではローカル有用性が0.7436でした。したがって、「どのseedや未知Bでも0.9以上」は保証できません。提出用は既定seedのみを使います。
- **データ移行性**：古い予選Bに本選式を当てた参考ハイブリッド評価は0.6076でした。これは公式の本選または予選得点ではなく、未知分布での保証には使えません。
- **稀なサブグループ**：U_rareは少数レコードに左右されやすく、少しの順位変化で大きく動きます。
- **Wald調整の限界**：係数と標準誤差を近づける局所的な方法であり、すべての生存曲線や相互作用を一致させるものではありません。
- **`time=10`固定攻撃**：入力Cを見ずに常に10と答える攻撃の補正得点は、基本的にBと背景データのtime分布で決まります。そのためCの加工だけで必ず0にすることはできません。今回の3背景分割では単純診断値が0.0721–0.0796でした。この目標は未達です。
- **次の検証**：正式提出前に別環境で同じSHA-256になることを確認し、Codabenchでは有用性と攻撃防御を別々に確認する必要があります。公式Anon、保護得点、φは現時点で未計算です。

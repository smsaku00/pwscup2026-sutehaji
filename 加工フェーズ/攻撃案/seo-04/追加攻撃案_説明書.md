# seo-03追加案：03a・03b・03c

## 何を追加したか

| ファイル | 役割 | 生成するもの |
|---|---|---|
| seo-03a-多重縮小生成比MIA.py | 複数設定で安定したMIA順位を探す | F_mia_から始まるCSV |
| seo-03b-容量付き全体割当AIA.py | Cの同じ行への対応を最大2回まで許す | F_aia_から始まるCSV |
| seo-03c-攻撃案差分分析.py | 元の03と追加案の予測を比較する | JSON診断レポート |

3ファイルは共通処理を元の`seo-03-正則化生成比と全体割当.py`から読み込む。4ファイルを同じフォルダに置く。03cは03a・03bも必要とする。必要な外部パッケージはNumPyとpandas。

## 03a：MIAの変更

元の03は共分散の縮小率35%に固定されていた。縮小率とは、属性間の相関をどれだけ弱めてモデルを安定化するかという設定である。値を大きくすると強い相関を信用しすぎる問題を抑えられるが、所属を示す相関も消す可能性がある。

03aは15・35・65・90%の4設定を使う。さらに次の4属性群で計算する。

1. 7連続属性全部。
2. 7連続属性からALTを除く。
3. 7連続属性からBMIを除き、timeを加える。
4. 7連続属性全部にtimeを加える。

4×4＝16本の正則化正規モデルによる対数密度比に、カテゴリ頻度比1本を加え、17本の順位の中央値を取る。最後に再び0～1へ順位化する。これは多数の設定が共通して高く評価する候補を上位へ置く方式である。

17本は独立した証拠ではない。同じデータから作った似たモデルであり、多数決が正解を保証するわけではない。カテゴリ比も17本のうちの1本なので、元03の20%重みとは影響の仕方が異なる。属性群と縮小率は未調整の実験設定である。

なお、この実装は正則化正規モデルの密度比であり、候補を追加して生成モデルの変化を測る論文のGen-LRAとは異なる。予備戦のGen-LRA成績を、この03aの成績として扱うことはできない。

## 03b：AIAの変更

元の03では、challenge数がC行数以下なら同じC行は1回しか割り当てられない。例えば2人のchallengeが同じ代表行に非常に近くても、一人は遠いC行へ押し出される。

03bは各C行に既定で2個の対応枠を作る。最初の枠は追加費用0、2個目は0.18の費用を加える。全体の「QI距離＋再利用費用」を最小化する。3枠以上へ増やす場合は、0番目から数えた枠番号の二乗×0.18を加える。challenge数がC行数×capacityを超える場合は停止する。

対応が決まった後のtime推定は元03と同じ。近い13行と割当先を使い、割当先の重みを3倍にして、±0.5年の重み付き時間窓を選ぶ。割当制約の変更を比較しやすい構成である。

複製や代表値化がある加工では有効な可能性がある一方、本当に一対一対応があるデータでは誤った重複対応が増える可能性がある。A_bgから再標本化したという事実だけで、capacity=2が適切とは判断できない。

## 実行方法

```powershell
python "seo-03a-多重縮小生成比MIA.py" --b B.csv --a-bg A_bg.csv --targets targets.json
python "seo-03b-容量付き全体割当AIA.py" --b B.csv --a-bg A_bg.csv --targets targets.json --capacity 2
python "seo-03c-攻撃案差分分析.py" --b B.csv --a-bg A_bg.csv --targets targets.json
```

targets.jsonの形式は元03と同じ。相対パスはJSONの場所が基準となる。03bのBは標準入力形式の検査にだけ使い、AIAの推定値には使わない。03aはchallengeのパス存在を検査するが、その内容を推定には使わない。

03a・03bは元03と同じ`--scope official --mia-columns mia_columns.json --self-team-id 5`の対象集合検査に対応する。公式提出前には当該フェーズの公式検査器でも確認する。

出力先は各スクリプトと同じフォルダ。既存CSVの内容が異なる場合は停止する。更新する場合は`--overwrite`を付ける。03cの既存JSONを更新するときも`--overwrite`が必要。03cは`--output report.json`で保存先を指定できるが、入力と同じパスには保存できない。

## 比較レポートの読み方

- MIA順位相関：1に近いほど元03と順番が似ている。全員同点の場合は未定義としてnull。
- MIA上位10人の一致率：例えば0.6なら10人中6人が共通。同点境界は固定した行順で選ぶため、同点が多いときは注意する。
- AIA変更割合：元03からtime予測が変わったchallengeの割合。
- AIA時間差平均：予測の変化幅を年単位で示す。
- C行の最大再利用数：03bで指定したcapacityを超えていないか確認する。

大きく変わったから改善した、同意するモデルが多いから正解、とは判断できない。03cは正解ラベルを使わず、どの仮定が結果を変えたかを調べる診断である。

## 検証と評価の区別

各ファイルの`--self-test`で基本動作を確認できる。`python -B verify_variants.py`は架空データで通常実行、CSV再現性、比較JSON生成、入力上書き拒否を確認する。小さな割当問題8件では全候補の総当たりと費用最小解を照合する。

今回の追加案について実データでの攻撃精度、予備戦・本戦の公式得点は測定していない。01～03の既存成績が存在しても、03a・03bへそのまま引き継げない。正式な精度比較では、同じ対象・同じ評価条件で元03と追加案を比べる必要がある。

# 背景対照で選別する最近傍AIA

## ① 基本情報

作成者seo、追加AIA案04、v1.0、2026-09-22。AIA専用。今回の模擬比較で高かった基準法を単独実行できるようにした案。新しい論文手法を発明したという意味ではない。従来のseo案は上書きせず、追加セットの別フォルダに保存した。

## ② ルールとの対応

基準はPWS_Cup2026_ルールブック_main-process-20260912、全25ページを確認。§3〜4（pp.5–9）の公開データの役割、§5（pp.10–13）の提出形式、§6.2–6.3（pp.19–22）のAIA採点、§7（pp.23–24）の利用条件を参照。

出力は全指定対象・全challengeに対するtime_hat。標的の正解timeを推定プログラムに与えない。MIAやトークン、ZIPは作らず、公式サイトにも送信しない。AIAの許容差は±0.5年。time_hat=0は有効な時間予測であって、公式の棄権記号ではない。

防御側の攻撃者最大値と、攻撃側の対象ごとのφ補正後平均は異なる。本案の実験では相手のφが不明なので公式得点を計算しない。

## ③ 概要と狙い

「Cに近い」だけでなく「背景の普通の人に比べて、Cに特に近いか」を見る。その証拠が強いchallengeにだけ、Cの最近傍のtimeを採用する。

Cに近くても、A_bgにも同じくらい近いなら、単にありふれた属性の人かもしれない。標的だけでなく対照も当てるとAIAの補正Rが下がるので、この違いを選別に使う。

この構成は最近傍によるレコード対応と背景対照の組合せであり、KDEではない。採用理由は今回の模擬比較の結果。背景比較や合成データの監査についての一般的な参考は[Stadlerら、USENIX Security 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/stadler)。この具体的な「75%」をその論文が推奨しているわけではない。

## ④ 攻撃手順

1. A_bgを基準に数値QIを尺度調整する。TG・ALTはlog1p、age・SBP・HDLは元の尺度から中央値を引きIQRで割る。
2. 数値5列の平均二乗差に、sex・prefectureが違う場合の1ずつを加えて距離にする。
3. challengeごとにCへの最小距離d_Cと、背景参照標本への最小距離d_Aを求める。
4. 証拠スコアを log((d_A+10^-8)/(d_C+10^-8)) とする。高いほど背景よりCに特に近い。
5. スコア上位75%のchallengeにはCの最近傍のtimeを回答する。残りはtime_hat=0を回答する。
6. ただし全QIがCと完全一致する場合は共通の完全一致処理を優先する。

完全一致処理では、一致したC行のtimeから±0.5年の件数を最大化する時間窓を選ぶ。複数候補の同点は昇順で決める。このため、実際に最近傍・完全一致の回答を採用する行数は75%を超える場合がある。

0を回答しても真のtimeが0.5以下なら的中する。したがって「残りを必ず外す」「標的と対照を完全に区別する」方式ではない。QIの一致も本人の同一性の証明にはならない。

## ⑤ 入力の使い方

- --b：共通CLIのために受け取るだけで、内容を読まない。自分のBも相手のBも照合に使わない。
- --a-bg：許可された背景13列。record_id付きならIDを検査して除く。最低128行。
- C：13列、最低8行。timeを回答候補に使う。
- challenge：challenge_row_idとage・SBP・TG・HDL・ALT・sex・prefectureのみ。
- targets.json：対象番号と2つの公開ファイルの対応。番号は処理分岐ではなく入出力の対応にのみ使う。

BMI・FPG・smokingはchallengeにないため距離計算には使わない。追加の正解列、未知列、重複ID、欠損、非有限値、不正な値域を拒否する。

## ⑥ パラメータ

KEEP_FRACTION=0.75、SEED=20260922。背景参照行数はmin(Cの行数,1200,A_bgの行数)。Cと背景の標本数の差が距離比較を支配しないようにする。ただしCが1200行を超える場合は背景を1200行に制限しているので、この効果が残る。

75%は今回比較した固定設定であり、どの加工法にも最適という意味ではない。背景標本・行順・同点処理・スレッド数を固定する。公開された実戦の正解で閾値を調整していない。

## ⑦ 適用条件

元行に近い行がCに残り、背景との差が対応の手掛かりになる場合に期待する。背景poolからの選択が元の個票に依存する場合にも候補になる。一方、Bと無関係な背景の無作為抽出だけなら、存在しない個票情報を復元できるとは限らない。

今回の人工noise・round・mixture条件では、選別しない1NNの方が高かった。選別で本当の標的を捨てる損失があるため、常に最近傍を改善する方式ではない。

## ⑧ 開発履歴

TXT、指定ルールブック、公式検証・採点コード、過去の一般的な実験結論を参照。3つの新しい原理の案を先に比較したところ、基準法の上位75%選別が平均的に高かったため、第4案としてコード化した。

過去の予備戦の全体成績を読んだ経緯はあるが、特定の相手番号・患者ID・非会員ID・正解time・過去の提出CSVを埋め込んでいない。同じ予備戦を完全な未見評価とは呼ばない。今回の数値比較は架空データである。

## ⑨ 実行方法

Python 3.12.14、NumPy 2.4.6、pandas 2.3.3、SciPy 1.17.1、scikit-learn 1.9.0で確認。

```powershell
python -m pip install numpy==2.4.6 pandas==2.3.3 scipy==1.17.1 scikit-learn==1.9.0
python "seo-04-選別最近傍AIA.py" --b B.csv --a-bg A_bg.csv --targets targets.json
```

targets.jsonの例：

```json
[{"target_k":7,"c_path":"C_7.csv","aia_challenge_path":"aia_challenge_7.csv"}]
```

相対パスはJSONの場所が基準。公式対象集合を確認するときは --scope official --mia-columns mia_columns.json --self-team-id 5 を追加する。5は自チーム番号の指定例であり、コードに固定していない。

出力はこのPythonと同じフォルダの F_aia_seo-04-選別最近傍AIA.csv。列はtarget_k,challenge_row_id,time_hat。異なる既存出力を変更するには --overwrite が必要。CSVは単独のAIA回答であり、正式ZIPへ同梱する際の標準名はF_aia.csv。AIAだけで正式提出一式が完成するとは限らない。

## ⑩ 確認結果

Pythonだけを一時フォルダにコピーして実行する独立性テスト、2対象への差替え、非完全一致QIでの実行、2回のCSVバイト一致、入力不変、B内容未使用、正解列・重複対象の拒否、指定版の公式AIA形式検査を実施。実測は検証結果.json。

処理時間・Windowsピークメモリ・ライブラリ版・出力ハッシュを記録。検査に合格しても攻撃精度が保証されたわけではない。

## ⑪ 評価結果

2乱数×6加工＝12条件の平均Rは0.770991。比較用の1NN上位75%選別は0.769547。わずかな差は共通の完全一致処理によるもので、別の強力な推定器が増えたという意味ではない。

単純1NNは0.654012、部分対応は0.712386、Shadow窓順位は0.714986、時間窓Boostingは0.442633だった。実戦の過去の提出点数とは母集団も評価条件も異なるため、数値を直接比べない。

φは不明なのでnull。公式本戦得点・protectionは未算出。詳細は比較結果_日本語.mdと模擬比較結果.json。対照の作り方・小標本・人工の加工の種類に依存し、公式点数の予測ではない。

## ⑫ 弱点と次の検証

Cのtime自体が元の人から切り離されていると、QI対応が正しくてもtimeは外れる。背景集団のずれ、距離の尺度、背景標本数、75%の固定閾値も弱点。

次に行うべき検証は、加工法自体を開発時に見ていない条件での比較と、許可された自己データを使った評価側・推定側の分離である。今回の平均だけで全対象への最適性は主張しない。

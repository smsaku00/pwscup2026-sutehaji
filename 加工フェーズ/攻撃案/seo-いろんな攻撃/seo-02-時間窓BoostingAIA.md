# 条件付き時間窓Boosting AIA

> 実測上の位置付け：今回は比較・研究用。12模擬条件の平均Rは0.4426で、単純1NNの0.6540、選別最近傍の0.7710を下回った。「より強いことを確認済みの案」としては推奨しない。異なる原理を試した記録として保存する。

## ① 基本情報

作成者seo、追加AIA案02、v1.0、2026-09-22。AIA専用。従来のseo-01〜04とは別の `aia_additional_20260922` フォルダで管理する追加セットであり、元の案を上書きしない。各Pythonは単独実行でき、ほかのseoファイルを読み込まない。

公式AIAは±0.5年の的中率を標的・対照で比べる。time_hatは確信度ではなく年数。本コードは全値を有限の[0,10]へ制限し、欠損・範囲外の特殊値を棄権記号にしない。命名や再現性確認はTXTのチーム内仕様。

## ③ 概要と狙い

timeの平均値ではなく、「この人がこの1年間の窓に入るか」を直接分類する。

[HistGradientBoostingClassifier公式資料](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingClassifier.html)の二値分類器を使用。条件付き推定による合成データの属性推論という位置付けは[Stadlerら（USENIX Security 2022）](https://www.usenix.org/conference/usenixsecurity22/presentation/stadler)を参照。時間窓と背景差の決定則は本実装の独自設計。

一般手法の論文実績と、PWSでのこの実装の強さは別である。背景から作った仮想データを用いた比較結果を別ファイルに記録し、実際の相手で強いと断言しない。

## ④ 攻撃手順

1. 公開QIの数値5列をlog/IQR変換し、sex・prefectureをone-hot化する。未知カテゴリ用の列も作る。
2. 0.5年から10年まで0.5年刻みの20中心について、Cのtimeが中心±0.5年に入るかという二値ラベルを作る。
3. 各窓についてHistGradientBoostingClassifierをCから学習する。全員同じラベルなら定数を返す。
4. A_bgからも同じ20モデルを学習し、背景だけで当たりやすい時間窓を調べる。
5. 各challengeでscore=p_C(window|QI)−0.90×p_A(window|QI)が最大の中心を答える。
6. 全QIの完全一致があれば共通の完全一致処理を優先する。

全案に共通の完全一致処理：公開QI全7列がCと一致する場合、一致したC行のtimeから±0.5年に最も多く入る窓を選ぶ。複数一致や異なるtimeも処理する。同点は昇順の候補の先頭。QI一致は本人の同一性や正解の証明ではない。

対象IDとchallenge IDは入出力対応だけに使用する。真の標的・対照ラベルを推定処理へ渡さず、チーム別の例外も設けない。

## ⑤ 入力の使い方

- `--b`：共通CLIのため受け取る。ファイル内容は一切読まない。加工元Bを渡して照合する攻撃にはならない。
- `--a-bg`：許可された背景13列。record_idがあれば形式検査後に除く。少なくとも128行。
- `c_path`：指定したCの13列。少なくとも8行。ID・真値の追加列は拒否。
- `aia_challenge_path`：challenge_row_idと公開QI7列だけ。隠されたtime等が追加されていれば拒否。

推定に使用するQIはage・SBP・TG・HDL・ALT・sex・prefecture。timeは背景・Cのみに存在する。BMI・FPG・smokingは実challengeの特徴には使わない。正解ファイルやutility_refを検索しない。

## ⑥ パラメータ

窓20個、max_iter=64、learning_rate=0.08、max_leaf_nodes=15、min_samples_leaf=12、l2_regularization=3、early_stopping=False、BACKGROUND_WEIGHT=0.90、random_state=20260922。

全共通：TG・ALTはlog1p、数値尺度は背景IQR、カテゴリは数値の大小として解釈しない。固定seed=20260922、数値計算と木は1スレッド。同点と行順を固定。終了は固定反復数で、途中に人が回答を選ぶ工程はない。

## ⑦ 適用条件

期待する条件：一人の対応行がなくても、QIとtimeの非線形な条件付き関係が残る加工。2年と10年に山がある場合にも、平均6年に潰さず時間窓を選べる。

入力形式が同じなら予備戦にも実行可能。ただし本戦のφ補正を予備戦得点へ混同しない。相手の加工法を既知とは仮定しない。

## ⑧ 開発履歴

TXT、指定PDF、公式検証・採点コード、従来の攻撃案、予備戦について保存された一般的な実験結論を参照。過去の相手別正解や非会員IDをコードには埋め込んでいない。過去の全体成績を読んだ履歴があるため、同じ予備戦への再適用を完全な未見評価とは呼ばない。

今回の実験は架空データだけで、対象の実B・真のtimeは使用していない。これらの人工加工を見て設計したため、模擬実験は開発診断である。文献手法に基づく発想を大会用に変更した実装で、文献そのものの再現・最先端性能の実証ではない。

## ⑨ 実行方法

確認環境：Python 3.12.14、NumPy 2.4.6、pandas 2.3.3、SciPy 1.17.1、scikit-learn 1.9.0。インストール例：

```powershell
python -m pip install numpy==2.4.6 pandas==2.3.3 scipy==1.17.1 scikit-learn==1.9.0
python "seo-02-時間窓BoostingAIA.py" --b B.csv --a-bg A_bg.csv --targets targets.json
```

`targets.json` の例。番号は書式例で、コードには固定していない。

```json
[{"target_k":7,"c_path":"C_7.csv","aia_challenge_path":"aia_challenge_7.csv"}]
```

相対パスはJSONのある場所が基準。公式対象を確認する場合は、`--scope official --mia-columns mia_columns.json --self-team-id 5`を追加する（5は自チームIDの指定例）。

出力はスクリプトと同じフォルダの `F_aia_seo-02-時間窓BoostingAIA.csv`。列はtarget_k,challenge_row_id,time_hat、UTF-8・LF・実数17桁。異なる既存回答には`--overwrite`が必要。MIAのダミー、ZIP、トークンは生成しない。

処理時間とWindowsのプロセス・ピークメモリは実行時JSONに記録する。実測の検証値は`検証結果.json`に保存し、測定不能時はnull。数値環境が違う場合のバイト一致は未確認。

## ⑩ 確認結果

別の検証プログラム `verify_and_benchmark.py` が、一時フォルダへこのPythonだけを置いて実行する。2対象への差替え、2回のCSVバイト一致、入力不変、B未使用、余分な正解列・重複対象の拒否を検査する。指定版の公式AIA検証関数にも同じ出力を渡す。検証実測は`検証結果.json`を参照。

## ⑪ 評価結果

`模擬比較結果.json` は人工集団の2乱数×6加工＝12条件に対する比較。1NN、5NN時間窓、1NN上位75%選別、全員10年と比較し、標的・対照の人数・正解数・的中率、希少側の同じ内訳、R・希少デッドゾーン補正Rを記録する。架空の希少フラグは評価側だけで使用する。

加工者の原表、公開背景、対照は別々に生成する。Shadow訓練に評価対象の個票を入れないが、加工法の種類は一部共通であり、未知加工法への独立検証ではない。φは未知なのでnullで記録し、0と仮定しない。公式本戦得点・最終匿名性・protectionは未算出。比較の要点は `比較結果_日本語.md` にまとめる。

## ⑫ 弱点と次の検証

単なる一般的なリスク予測は対照でも当たるため、AIA得点につながらない。Cが集団の関係だけを保存した場合は成功率が高くても差が小さい。モデル確率は未校正で、背景項を引く式は公式Rの直接最適化ではない。小標本の窓は不安定。

複数方法で予測が一致しても正解とは断定できない。実対象で比較するには許可された検証条件と非公開採点が必要。模擬結果から特定のチームIDを選別して答えを差し替える処理は含めない。

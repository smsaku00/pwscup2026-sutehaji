## ③ 概要と狙い

本人候補との類似度を、5つの連続属性全てを使う見方と、1属性ずつ除く見方の計6通りで計算する。1列の加工で距離が崩れる場合に備える設計である。背景で珍しい一致が得られる見方を重くし、複数候補のtimeから幅1年の最も重い区間を選ぶ。公式1-NNとの違いは、部分属性・柔らかいカテゴリ条件・候補分布からの年数選択。効果は仮説であり実測の攻撃成績はない。

## ④ 攻撃手順

1. A_bgの5連続属性の標本標準偏差で各差を割る。定数列または1行の背景では尺度1を使う。
2. 全5属性と各1属性を除いた4属性の計6ビューを作る。各ビューの候補対数重みは `L = -0.5 × mean(標準化差²) / h² - 2×性別不一致 - 1×県不一致`。カテゴリ不一致だけでは排除しない。
3. C内で各ビューの重みをsoftmax正規化する。A_bgにも同じカーネルを当て、ビューの希少性 `r = clip(-log(mean(exp(L_bg))), 0, 8)` を計算する。logsumexpを使い、極小値の計算を安定化する。
4. ビューを `exp(r)` の比率で混合する。この重みは校正済みの本人確率ではない。背景との対比は一致しやすさの尺度であり、A_bgに本人がいるとは仮定しない。
5. Cのtimeを並べ、幅1年以内に入る重みの合計が最大の窓を選び、その窓に含まれる最小timeと最大timeの中点を回答する。同じ最大質量との差が1e-12以内なら中点が大きい方を選ぶ。
6. 全行を同じ規則で処理する。学習・対象別の手動切替・棄権はない。

## ⑤ 入力の使い方

A_bgは5属性の尺度と6ビューの一致しやすさに使用。A_bgのtimeは予測には使わない。Cは7属性とtime、課題は7属性と行IDを使う。

- `--b`: 共通引数として必須。ファイルの存在だけを検査する。内容・ID・ハッシュを読み込まず、学習・照合・推定に使わない。
- `--a-bg`: 配布形式14列の背景CSV。record_idは一意性だけ検査し、予測特徴に使わない。
- C: 配布形式からrecord_idを除いた13列。指定されたファイルだけ読む。加工元の非公開BやB_selfは受け取らない。
- 課題: challenge_row_idと7属性の8列。真のtime・is_rare・標的対照ラベルが追加された表は拒否する。
- 読み込むC・背景は型・値域・欠損・列名重複を検査する。年齢40–74、検査値の範囲、47県名、二値列、timeは指定版に固定。列順は任意だが余分な列を拒否する。Cの完全重複行は受理し、ID重複とは区別する。
- Cの行数は入力から読み、1,049を埋め込まない。加工元Bを読まないため、Cと非公開の加工元Bの人数一致をこの攻撃プログラムで証明することはできない。
- targets.jsonは `target_k`, `c_path`, `aia_challenge_path` の3項目だけ。同じtarget_kの重複は拒否。Cや課題の相対パスはtargets.jsonの親フォルダ基準。
- 評価専用の標的・対照・希少ラベル・正解time・φ_i・採点結果は、攻撃プログラムの入力に含めない。IDは対応付け・整列・同点処理にのみ使い、正解を埋め込まない。

## ⑦ 適用条件

一部の属性が元の個人に近いまま残り、timeも保たれている加工を想定。属性を減らすと偶然の一致が増える。強い複数列の加工、転帰の独立な再割当、完全な合成では弱い可能性がある。6ビューの平均化が、正しい1ビューの情報を薄める可能性も残る。未知の対象へ同じ規則を適用できることと、未知対象で強いことは別である。

推定に追加の公開情報、対象の加工手法名、提出後の採点結果、他チームのφ_iは不要。必要ファイルが欠ける場合は理由を示して終了する。カテゴリや値域を別版へ自動拡張しない。規定の改訂があれば指定版との差を確認してから変更する。

## ⑨ 実行方法

Python 3.11以上を想定。確認環境はPython 3.12.7、macOS arm64、NumPy 2.4.6、pandas 2.3.3、SciPy 1.17.1、scikit-learn 1.9.0。03だけがscikit-learnをimportする。実測メモリの取得にresourceを使うため、macOS/Linux向け。Windowsは未確認。

```sh
python -m pip install -r requirements.txt
python "TT-01-部分属性照合.py" --b "B.csv" --a-bg "A_bg.csv" --targets "targets.json"
```

targets.jsonの例（2は書式例で、固定IDではない）:

```json
[
  {
    "target_k": 2,
    "c_path": "C_名前-01-手法名.csv",
    "aia_challenge_path": "aia_challenge_2.csv"
  }
]
```

指定版の公式キットを別途入手し、ルートを `starter-kit/` に配置してから、このフォルダで実行例を試す。キットとデータはこのリポジトリには含まれない:

```sh
python "TT-01-部分属性照合.py" --b "starter-kit/participant_data/B_practice.csv" --a-bg "starter-kit/participant_data/A_bg.csv" --targets "targets.練習.json"
```

公式対象一覧を使う場合:

```sh
python "TT-01-部分属性照合.py" --b "B.csv" --a-bg "A_bg.csv" --targets "targets.json" --target-set official --mia-columns "mia_columns.json" --self-team-id "$ATTACKER_TEAM_ID"
```

`ATTACKER_TEAM_ID` は利用者が正式な自チームIDを設定する変数。スクリプトはチーム番号を推測しない。公式対象集合から自チームを除いた集合との完全一致を要求する。自チームのローカル検証は既定のlocalとして別実行する。`--b`, `--a-bg`, `--targets`, `--mia-columns`自体の相対パスは起動時の作業フォルダ基準である。

出力は常に**スクリプトと同じフォルダ**:

- `F_aia_TT-01-部分属性照合.csv`: target_k, challenge_row_id, time_hatの3列、指定全行。time_hatは確信度ではなく年数。
- `実行記録_TT-01-部分属性照合.json`: コード・入力・出力のSHA-256、対象集合、設定、環境、時間、メモリ。時間などが変動するためJSONのバイト一致は要求しない。

実測（練習対象1・2、合計652課題行、2回）: 0.680秒 / 0.682秒。プロセスのピークRSSは 100.4 MiB / 100.5 MiB。時間は引数解析後の読み込み・推定・CSV保存までで、Python起動とライブラリimportの時間を含まない。メモリはimport分も含む。対象数や行数が増えた場合の時間・メモリは未測定。

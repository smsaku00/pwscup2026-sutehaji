## ③ 概要と狙い

Cの7属性からtimeの条件付き分布を、ExtraTreesの葉に含まれる学習行で推定する。通常の回帰平均ではなく、±0.5年以内の的中に対応する最大質量区間を選ぶ。個人の照合が難しい集約・合成でも関係が残る可能性を調べる案である。対照も同程度に当たるなら攻撃力は伸びない。

## ④ 攻撃手順

1. 5連続属性はA_bgの標本標準偏差で割る。性別は0/1、県は47都道府県の固定順でone-hot化する。計53特徴量。FPG、BMI、喫煙、課題のonset/deathは特徴にしない。
2. Cの特徴量とtimeだけでExtraTreesRegressorを学習する。Cの行順は全属性で固定してから学習する。乱数は20260920、並列数は1。
3. 課題が各木で到達した葉に属するCの学習行へ、`1/(木の本数×その葉の学習行数)` の重みを足す。全木の平均に相当する分布を作る。予測の確率校正は未確認。
4. Cのtimeの幅1年の窓で重み合計が最大のものを選び、含まれる最小timeと最大timeの中点を返す。最大質量との差が1e-12以内なら中点が大きい方を採用する。10年への集中を含め、観測された追跡年数そのものを対象にする。
5. A_bgのtimeや課題の真値による学習・早期停止・モデル選択はない。対象ごとに同一設定で学習し、全行へ回答する。棄権・手動切替はない。

## ⑤ 入力の使い方

A_bgは5連続属性の尺度だけに使用し、そのtimeを学習に使用しない。学習はCの7属性→time、課題は7属性と行IDを使う。死亡を含む観測追跡年数の推定であり、糖尿病の潜在的な発症時刻を生存解析で外挿する処理ではない。

- `--b`: 共通引数として必須。ファイルの存在だけを検査する。内容・ID・ハッシュを読み込まず、学習・照合・推定に使わない。
- `--a-bg`: 配布形式14列の背景CSV。record_idは一意性だけ検査し、予測特徴に使わない。
- C: 配布形式からrecord_idを除いた13列。指定されたファイルだけ読む。加工元の非公開BやB_selfは受け取らない。
- 課題: challenge_row_idと7属性の8列。真のtime・is_rare・標的対照ラベルが追加された表は拒否する。
- 読み込むC・背景は型・値域・欠損・列名重複を検査する。年齢40–74、検査値の範囲、47県名、二値列、timeは指定版に固定。列順は任意だが余分な列を拒否する。Cの完全重複行は受理し、ID重複とは区別する。
- Cの行数は入力から読み、1,049を埋め込まない。加工元Bを読まないため、Cと非公開の加工元Bの人数一致をこの攻撃プログラムで証明することはできない。
- targets.jsonは `target_k`, `c_path`, `aia_challenge_path` の3項目だけ。同じtarget_kの重複は拒否。Cや課題の相対パスはtargets.jsonの親フォルダ基準。
- 評価専用の標的・対照・希少ラベル・正解time・φ_i・採点結果は、攻撃プログラムの入力に含めない。IDは対応付け・整列・同点処理にのみ使い、正解を埋め込まない。

## ⑥ パラメータ

全設定はPythonファイル冒頭の定数にある。設定値は初期仮説で、評価対象の正解による最適化は未実施。

## ⑦ 適用条件

属性とtimeの関係がCに残る場合を想定。個人の行の対応は仮定しない。ただし、集団の一般則は対照にも当たるため、通常の予測精度向上だけではAIA攻撃力の改善にならない。葉の平滑化で希少な早期の転帰が薄まり、10年回答へ偏る可能性もある。

推定に追加の公開情報、対象の加工手法名、提出後の採点結果、他チームのφ_iは不要。必要ファイルが欠ける場合は理由を示して終了する。カテゴリや値域を別版へ自動拡張しない。規定の改訂があれば指定版との差を確認してから変更する。

## ⑨ 実行方法

Python 3.11以上を想定。確認環境はPython 3.12.7、macOS arm64、NumPy 2.4.6、pandas 2.3.3、SciPy 1.17.1、scikit-learn 1.9.0。03だけがscikit-learnをimportする。実測メモリの取得にresourceを使うため、macOS/Linux向け。Windowsは未確認。

```sh
python -m pip install -r requirements.txt
python "TT-03-条件分布推定.py" --b "B.csv" --a-bg "A_bg.csv" --targets "targets.json"
```

targets.jsonの例（2は書式例で、固定IDではない）:

```json
[
  {
    "target_k": 2,
    "c_path": "C_名前-01-手法名.csv",
    "aia_challenge_path": "aia_challenge_2.csv"
  }
]
```

指定版の公式キットを別途入手し、ルートを `starter-kit/` に配置してから、このフォルダで実行例を試す。キットとデータはこのリポジトリには含まれない:

```sh
python "TT-03-条件分布推定.py" --b "starter-kit/participant_data/B_practice.csv" --a-bg "starter-kit/participant_data/A_bg.csv" --targets "targets.練習.json"
```

公式対象一覧を使う場合:

```sh
python "TT-03-条件分布推定.py" --b "B.csv" --a-bg "A_bg.csv" --targets "targets.json" --target-set official --mia-columns "mia_columns.json" --self-team-id "$ATTACKER_TEAM_ID"
```

`ATTACKER_TEAM_ID` は利用者が正式な自チームIDを設定する変数。スクリプトはチーム番号を推測しない。公式対象集合から自チームを除いた集合との完全一致を要求する。自チームのローカル検証は既定のlocalとして別実行する。`--b`, `--a-bg`, `--targets`, `--mia-columns`自体の相対パスは起動時の作業フォルダ基準である。

出力は常に**スクリプトと同じフォルダ**:

- `F_aia_TT-03-条件分布推定.csv`: target_k, challenge_row_id, time_hatの3列、指定全行。time_hatは確信度ではなく年数。
- `実行記録_TT-03-条件分布推定.json`: コード・入力・出力のSHA-256、対象集合、設定、環境、時間、メモリ。時間などが変動するためJSONのバイト一致は要求しない。

実測（練習対象1・2、合計652課題行、2回）: 0.358秒 / 0.345秒。プロセスのピークRSSは 189.3 MiB / 191.9 MiB。時間は引数解析後の読み込み・推定・CSV保存までで、Python起動とライブラリimportの時間を含まない。メモリはimport分も含む。対象数や行数が増えた場合の時間・メモリは未測定。

全体は `R_all=clip((p_m-p_c)/(1-p_c),0,1)`。希少側は指定版のz=1.64の標準誤差による許容幅を用い、全体との大きい方を対象の成功度とする。空群は評価不能として記録する。p_c=1などの退化条件は指定版実装を明記して扱う。本戦攻撃力は `mean_i clip(a_i-phi_i,0,1)`。平均的中率を先にまとめてから式へ入れたり、表示された全体・希少平均を足したりしない。加工側匿名性は攻撃者について最大を取ってからφ_iを1回差し引く別集計である。

比較では、弱い摂動、一部列の強い変更、集約、合成、timeの変更を含める。予備戦公式採点、本戦式による参考評価、模擬評価を別列に記録する。開発用と最終比較用を分け、最終結果を見て変更した時点でそのデータは開発用へ移す。

## ⑫ 弱点と次の検証

属性とtimeの関係がCに残る場合を想定。個人の行の対応は仮定しない。ただし、集団の一般則は対照にも当たるため、通常の予測精度向上だけではAIA攻撃力の改善にならない。葉の平滑化で希少な早期の転帰が薄まり、10年回答へ偏る可能性もある。

標的・対照を混ぜたまま予測し、採点時だけ両者の的中率を比較する。Cを用いた上積みがなければ、精度が高くても攻撃案としては採用しない。

初期設定の根拠は推定原理と実装上の安定性であり、最良性能の実証ではない。模擬実験や同一課題の最高値だけで本戦の有効性を結論付けない。

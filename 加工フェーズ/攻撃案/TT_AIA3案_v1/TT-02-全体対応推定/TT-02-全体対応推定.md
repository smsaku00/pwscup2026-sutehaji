## ③ 概要と狙い

課題を1行ずつ独立に最近傍へ結び付ける代わりに、Cの各行の利用回数を1回に制限して全体の対応を決める。対応が弱い行には「対応なし」を許し、背景による予測を返す。01と異なり、距離の部分属性化ではなく、課題間の候補競合を利用する。効果は仮説であり実測の攻撃成績はない。

## ④ 攻撃手順

1. 公式参照法と同じ5連続属性の標準偏差標準化とRMS距離を使う。性別・県一致の候補を使い、空なら性別一致、さらに空なら全Cへ戻す。
2. 内容で整列したA_bgから最大1,024行を等間隔の添字で取り出し、それぞれのCへの最近傍距離を計算する。乱数抽出はしない。
3. 課題行と同じ性別・県の背景校正行が20以上なら、その最近傍距離の5%点を閾値にする。20未満なら性別、さらに20未満なら全校正行を使う。閾値の下限は1e-9。これは対応なしのコスト設定であり、標的確率ではない。
4. 候補コストを `min(距離/閾値, 2)` にする。課題行数と同数のダミー枠をコスト1で加え、SciPyのlinear_sum_assignmentで総コストを最小化する。Cの各行と各ダミー枠の容量は1。標的人数の半分などを強制しない。
5. Cに対応し、かつコストが厳密に1未満ならその行のtimeを返す。それ以外はA_bgの同じブロック規則の25近傍を使用する。同点の25番目は全て含め、距離を近傍の最大距離で割ったガウス重みを用い、幅1年の最大質量区間の中点を返す。
6. 対応なしでも行を削除せず年数を回答する。自己攻撃と公式攻撃を分離する。手動切替や棄権はない。

## ⑤ 入力の使い方

A_bgは距離の尺度・対応なし閾値・対応なし時のtime予測に使用。Cは7属性とtime、課題は7属性と行IDを使う。

- `--b`: 共通引数として必須。ファイルの存在だけを検査する。内容・ID・ハッシュを読み込まず、学習・照合・推定に使わない。
- `--a-bg`: 配布形式14列の背景CSV。record_idは一意性だけ検査し、予測特徴に使わない。
- C: 配布形式からrecord_idを除いた13列。指定されたファイルだけ読む。加工元の非公開BやB_selfは受け取らない。
- 課題: challenge_row_idと7属性の8列。真のtime・is_rare・標的対照ラベルが追加された表は拒否する。
- 読み込むC・背景は型・値域・欠損・列名重複を検査する。年齢40–74、検査値の範囲、47県名、二値列、timeは指定版に固定。列順は任意だが余分な列を拒否する。Cの完全重複行は受理し、ID重複とは区別する。
- Cの行数は入力から読み、1,049を埋め込まない。加工元Bを読まないため、Cと非公開の加工元Bの人数一致をこの攻撃プログラムで証明することはできない。
- targets.jsonは `target_k`, `c_path`, `aia_challenge_path` の3項目だけ。同じtarget_kの重複は拒否。Cや課題の相対パスはtargets.jsonの親フォルダ基準。
- 評価専用の標的・対照・希少ラベル・正解time・φ_i・採点結果は、攻撃プログラムの入力に含めない。IDは対応付け・整列・同点処理にのみ使い、正解を埋め込まない。

## ⑦ 適用条件

本人とCの行の対応がある程度残る加工を想定。合成・集約・再標本化では1人1行の仮定が崩れ、対応を奪い合う制約が悪化につながる。完全に同じC行が複数あっても各行を独立の枠として扱う。県・性別が加工されていると公式型の絞り込みが本人を排除し得る。対応なし閾値を背景から求めても、対照の分布と背景の分布は完全には同じでない。

推定に追加の公開情報、対象の加工手法名、提出後の採点結果、他チームのφ_iは不要。必要ファイルが欠ける場合は理由を示して終了する。カテゴリや値域を別版へ自動拡張しない。規定の改訂があれば指定版との差を確認してから変更する。

## ⑨ 実行方法

Python 3.11以上を想定。確認環境はPython 3.12.7、macOS arm64、NumPy 2.4.6、pandas 2.3.3、SciPy 1.17.1、scikit-learn 1.9.0。03だけがscikit-learnをimportする。実測メモリの取得にresourceを使うため、macOS/Linux向け。Windowsは未確認。

```sh
python -m pip install -r requirements.txt
python "TT-02-全体対応推定.py" --b "B.csv" --a-bg "A_bg.csv" --targets "targets.json"
```

targets.jsonの例（2は書式例で、固定IDではない）:

```json
[
  {
    "target_k": 2,
    "c_path": "C_名前-01-手法名.csv",
    "aia_challenge_path": "aia_challenge_2.csv"
  }
]
```

指定版の公式キットを別途入手し、ルートを `starter-kit/` に配置してから、このフォルダで実行例を試す。キットとデータはこのリポジトリには含まれない:

```sh
python "TT-02-全体対応推定.py" --b "starter-kit/participant_data/B_practice.csv" --a-bg "starter-kit/participant_data/A_bg.csv" --targets "targets.練習.json"
```

公式対象一覧を使う場合:

```sh
python "TT-02-全体対応推定.py" --b "B.csv" --a-bg "A_bg.csv" --targets "targets.json" --target-set official --mia-columns "mia_columns.json" --self-team-id "$ATTACKER_TEAM_ID"
```

`ATTACKER_TEAM_ID` は利用者が正式な自チームIDを設定する変数。スクリプトはチーム番号を推測しない。公式対象集合から自チームを除いた集合との完全一致を要求する。自チームのローカル検証は既定のlocalとして別実行する。`--b`, `--a-bg`, `--targets`, `--mia-columns`自体の相対パスは起動時の作業フォルダ基準である。

出力は常に**スクリプトと同じフォルダ**:

- `F_aia_TT-02-全体対応推定.csv`: target_k, challenge_row_id, time_hatの3列、指定全行。time_hatは確信度ではなく年数。
- `実行記録_TT-02-全体対応推定.json`: コード・入力・出力のSHA-256、対象集合、設定、環境、時間、メモリ。時間などが変動するためJSONのバイト一致は要求しない。

実測（練習対象1・2、合計652課題行、2回）: 0.255秒 / 0.254秒。プロセスのピークRSSは 147.9 MiB / 154.5 MiB。時間は引数解析後の読み込み・推定・CSV保存までで、Python起動とライブラリimportの時間を含まない。メモリはimport分も含む。対象数や行数が増えた場合の時間・メモリは未測定。

全体は `R_all=clip((p_m-p_c)/(1-p_c),0,1)`。希少側は指定版のz=1.64の標準誤差による許容幅を用い、全体との大きい方を対象の成功度とする。空群は評価不能として記録する。p_c=1などの退化条件は指定版実装を明記して扱う。本戦攻撃力は `mean_i clip(a_i-phi_i,0,1)`。平均的中率を先にまとめてから式へ入れたり、表示された全体・希少平均を足したりしない。加工側匿名性は攻撃者について最大を取ってからφ_iを1回差し引く別集計である。

比較では、弱い摂動、一部列の強い変更、集約、合成、timeの変更を含める。予備戦公式採点、本戦式による参考評価、模擬評価を別列に記録する。開発用と最終比較用を分け、最終結果を見て変更した時点でそのデータは開発用へ移す。

## ⑫ 弱点と次の検証

本人とCの行の対応がある程度残る加工を想定。合成・集約・再標本化では1人1行の仮定が崩れ、対応を奪い合う制約が悪化につながる。完全に同じC行が複数あっても各行を独立の枠として扱う。県・性別が加工されていると公式型の絞り込みが本人を排除し得る。対応なし閾値を背景から求めても、対照の分布と背景の分布は完全には同じでない。

摂動だけでなく、再標本化・集約・合成を含めて1行1対応の仮定を検証する。閾値の変更は開発分割に限定し、最終比較で対象別に当たる設定を選ばない。

初期設定の根拠は推定原理と実装上の安定性であり、最良性能の実証ではない。模擬実験や同一課題の最高値だけで本戦の有効性を結論付けない。

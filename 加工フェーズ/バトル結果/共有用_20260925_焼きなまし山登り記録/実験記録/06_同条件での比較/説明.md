# 前提

- 根拠：本戦Bを用いたローカル模擬実験。有用性Uのみ公式コードによる自己採点。
- 初回の約1時間実験と長時間探索は、最後に確認した候補・確認データが異なっていた。
- 今回は初回の合格案と長時間版の5案を両方の確認セットで評価し、条件をそろえる。
- 比較対象は計8つ。元のZhang11、元のZhang04、初回合格案、長時間版の5候補。

# 仮説

- 初回の合格案を今回の確認セットで評価しないまま、探索時間の長短による優劣は比較できない。
- 同じ候補・同じ攻撃・同じ確認データ・同じ採用条件を用いれば、以前の合否の違いを切り分けられる。

# 分析方法

- C、背景、攻撃プログラム、確認データをコピーして固定。元ファイルは変更していない。
- 候補が元のCから記録された交換だけで再現できることを確認。
- AIA：共通の探索用2組＋初回の確認用4組＋長時間版の確認用4組＝計10組。8つのC×10組×12攻撃＝960通りを新規計算。
- MIA：初回3組＋長時間版3組＝計6組。8つのC×6組×4攻撃＝192通りを元の攻撃プログラムで新規計算。
- AIAの計算共有には以前にCLIとの一致を検証済みの採点コードを使用。保存済み予測がある組み合わせでは今回の予測・的中判定も照合。
- MIAは各組26標的＋1,023対照。FPR=1%でのTPRを公式コードで計算。真の希少対照ラベルはないため、公式の希少MIAは未評価。
- 各候補は自分の元のCを基準にする。確認セットをまたぐ絶対値の大小だけで改善を判断しない。
- 採用条件は以前と同じ：U維持、共通探索2組の最大AIA改善、確認387人組の最大AIA改善、確認163人3組で最大AIA悪化なし、MIA4手法×3組の全比較で悪化なし。
- 今回は新しい候補を探索していない。既に見た確認セットをそろえた比較であり、未知データによる検証ではない。
- 再現：プロジェクトのPython環境で `分析.py` を実行し、資料用環境で `資料作成.py` を実行する。入力・出力の記録は `計画.json`、`比較集計.json`、`検証結果.json`。

# 結論

- 初回合格案は初回の確認セットで合格を再現した。
- 同じ案を長時間版の確認セットで評価すると、163人組2・組3でAIAが悪化し不合格。MIAは両方で悪化なし。
- 長時間版の5候補はいずれも、今回の両確認セットで全採用条件を満たさなかった。
- 6候補ともUは維持しているが、両セットで合格した候補はない。
- 387人の確認パネルでは、6候補とも両セットで最大AIAが改善している。不合格は163人パネルやMIAの一部悪化による。
- この結論は確認した6候補についてのもの。探索した全候補に対する不合格の証明ではない。

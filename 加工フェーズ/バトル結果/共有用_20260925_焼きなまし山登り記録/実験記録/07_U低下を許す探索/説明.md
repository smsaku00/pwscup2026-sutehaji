# 前提

- ユーザーが20分程度の探索を承認。16並列、Zhang11→Zhang04の順で実行する。
- Uの下限は元案、0.915、0.910、0.900。元案・既存の探索最良案から、従来と同じ6属性の交換で探す。
- 根拠はローカル模擬実験。有用性のみ公式コードによる自己採点。

# 仮説

- U維持条件で除外した候補に、AIAの低いものがある可能性がある。
- Uを下げること自体を目標にせず、同じ候補群から各U下限で最良のAIAを比較する。

# 分析方法

- AIA探索用2組はこれまでと同じ。12攻撃の最大値を下げる山登りを行う。
- 年齢・SBP・TG・HDL・ALT・timeの交換。timeは同じonset/death群の有効な交換のみ。総交換は元案から10回以内。
- 4条件で同じ候補群の計算を共有し、各条件の上位経路を残す。独立に4回実験する設計ではない。
- 約20分には準備・確認を含む。最後の5分を新しい確認パネルとMIAに残す。小さな候補群の区切りで終了する。
- 新しい確認パネルは387標的＋同数対照1組と163標的＋同数対照3組。MIAは26標的＋1,023対照を3組。
- 確認用の乱数は202609242223系。候補を固定するまで確認用の攻撃得点は参照しない。
- 過去の予測は整合性チェックにのみ使用し、今回の予測は作り直す。共通の背景処理のみ共有する。
- 実行はプロジェクトのPython環境で `分析.py`。進捗は `進捗確認.command`。

# 結論

- 2,912候補を探索。U維持なら除外される61候補も評価したが、Uの下限を緩めたことによる最良探索AIAの更新はなかった。
- 実際にUが下がる参考案も1つ追加確認した。元案より改善したが、Uを維持した既存最良案には届かなかった。
- 要点は `共有用/00_結果まとめ.md`、詳細は `共有用/読みやすい比較表.csv`。追加確認は `U低下案の追加確認.py`、結果整理は `結果整理.py` で再現できる。
- 本番の匿名性得点や希少MIAは予測しない。既存の有限データを使うため、確認パネル間には個人の重複がある。

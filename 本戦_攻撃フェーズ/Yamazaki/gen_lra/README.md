# Gen-LRA を理解する — PWS Cup 2026 の MIA

このコードは、Ward・Wang・Cheng の [Gen-LRA 論文（Algorithm 1）](https://arxiv.org/html/2508.21146v2) を、PWS Cup 2026 の `F_mia.csv` に合わせて実装したものです。MIA（メンバーシップ推論攻撃）は、「ある人が、対象チームの合成データ `C_k` を作る際の元データに含まれていたか」を推定します。生成モデルの内部や再学習の権限は必要ありません。

## 三つのデータの役割

| 記号 | 大会のファイル | 意味 |
| --- | --- | --- |
| 候補 `x` | 自チームの `B.csv` の各行 | 対象チームの元データにもいたか調べる人 |
| 背景 `R` | `A_bg.csv` | 一般にどんな人がどの程度いるかを示す比較対象 |
| 合成 `S` | 対象チームの `C_<k>.csv` | そのチームが公開した合成データ |

`record_id` は回答行を指定するために使い、近さや密度の計算には入れません。対象チームごとに `C_<k>.csv` を替えて、全候補のスコアを計算します。

## 直感：候補を背景に一人加える

背景データの各行の周りに、なだらかな「山」を置きます。山を重ねたものが **KDE（カーネル密度推定）** で、ある特徴の組合せが背景でどれくらい自然かを表します。

1. 候補 `x` に近い合成行を `C_k` から 10 行選びます。
2. その 10 行が、背景 `R` だけの KDE でどれくらい自然かを測ります。
3. `R` に `x` を一人加えた KDE でも同じ 10 行を測ります。
4. 尤度の増加が大きい候補ほど、`C_k` にその人の影響が残った可能性が高い、と順位づけます。

例えば、背景では珍しい特徴の人 `x` の近くに合成行が複数あるなら、`x` を加えるとその場所の密度が大きく増えます。ありふれた特徴なら、背景に似た人がすでに多く、一人を加えた影響は小さくなります。単に「近い合成行があるか」に加え、**背景と比べてその近さがどれほど特異か**を見ているわけです。

近くの行だけを使うのは、遠くの合成行に `x` の痕跡がほぼないためです。`k=10` は証拠を何行から集めるかを決めます。小さい `k` は局所的なコピーに敏感で、大きい `k` は広がった痕跡を拾えます。

## スコアの式と読み方

`R` の行数を `m`、候補 `x` に最も近い合成行の集合を `N_k(x,S)` とします。Gaussian KDE を `p_R` と書くと、生のスコアは次の式です。

$$
a(x,S,R)=\sum_{s\in N_k(x,S)}
\left[\log p_{R\cup\{x\}}(s)-\log p_R(s)\right].
$$

各項は「候補を加えたとき、その合成行の尤度が何倍になったか」の対数です。**大きいほどメンバーらしい**という向きで、負の値もあり得ます。

この実装では、候補を加える前後で同じ帯域幅 `h`（山の広がり）を使います。その場合、KDE を候補ごとに学習し直さず、次の**厳密な更新式**で同じ値を計算できます。

$$
\frac{p_{R\cup\{x\}}(s)}{p_R(s)}
=\frac{m}{m+1}
\left(1+\frac{K_h(s-x)}{\sum_{r\in R}K_h(s-r)}\right).
$$

分子の `K_h(s-x)` は候補と合成行の近さ、分母の和はその合成行の背景での密度を表します。分母が小さい場所で候補の山が重なると、スコアが強く上がります。

大会の提出値は、生のスコアを**対象チームの列ごとに順位の百分位（0～1）**へ変換したものです。順位は保たれますが、`0.8` を「所属確率 80%」とは解釈できません。高順位でも、偶然似た合成行が生まれた可能性は残ります。

## このデータ向けの選択と限界

- 既定では `record_id` を除く 13 列を使います。`age` や検査値に加え、`time`・`onset`・`death` も含みます。
- `prefecture` は共有の順序番号に変換し、各列を `A_bg` の平均と標準偏差で標準化します。これは混合データを Gaussian KDE に入れるための便宜的な符号化です。県名の番号順に距離の意味があるわけではありません。
- 帯域幅は標準化後の多変量 Silverman 則で決めます。広すぎると局所的な痕跡が薄まり、狭すぎると背景密度の推定が不安定になります。
- `--features covariates` は転帰の 3 列を外し、`--features continuous` は年齢と検査値の 7 列だけを使います。`--k` と `--bandwidth-scale` も変更できます。

背景データが対象チームの母集団をよく表していない場合や、生成器が個人の痕跡を残さない場合、順位の信頼性は下がります。手元には対象チームの真の所属ラベルがないため、この大会データでの TPR@FPR=0.01 は測定していません。

## 再実行と検証

`attack_data` に `B.csv`（練習では `B_practice.csv`）、`A_bg.csv`、`mia_columns.json`、対象の `C_<k>.csv` を置きます。対象ファイルが `targets/` にまとまっていても読み込めます。

```bash
cd pwscup2026-kit/starter
uv sync
uv run python /path/to/gen_lra/run_gen_lra.py --dist /path/to/attack_data --out /path/to/F_mia.csv
```

`F_mia.csv` は `record_id` と `mia_columns.json` の指定列を、その順序で出力します。コード内の数式を明示的な KDE 再学習と照合するテストも付属します。

```bash
cd /path/to/gen_lra
python -m unittest -v test_gen_lra.py
```

今回のデータでは 1,049 行・23 対象列を生成し、参照 AIA の `F_aia.csv` と `token.txt` を入れた一時 ZIP が公式 `validate` のパッケージ検査・論理検査を通過しました。ローカルの配布物にはトークン登録台帳がないため、登録照合は大会側の検証で行われます。トークンと元データはこのコード一式に含めていません。

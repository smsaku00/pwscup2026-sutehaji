# 本戦2回目のMIA回答と安全確認

**[今回使う F_mia.csv](結果/F_mia.csv) を作成しました。全体用はseo-02、希少用は102通りを区別できる2回目の設定です。** 1,049人 × 22チーム。今回はMIAだけの作成で、大会へは未提出です。AIA、token、提出ZIPは含みません。

## 1 前提

ユーザーが承認した「全体は初回と異なる有力手法、希少は検証済みの2回目」を組み合わせました。自チームは28、対象は0〜17、22、25、26、27の22チームです。【配布データ】

| 対象 | 人数 | 今回の値 |
|---|---:|---|
| 希少以外で所属が不明 | 875人 | seo-02の順位に応じて0.55より大きく0.95以下 |
| 希少以外で非会員と確認済み | 150人 | 0 |
| 希少で所属が不明 | 11人 | 全対象チームで0.4 |
| 希少で非会員と確認済み | 13人 | チーム別の必要人数だけ0.4、残り0.1 |

希少の非会員13人は、点数から人数を読み分けるための調整に使います。**この13人を一律に0へ変更すると、設計が崩れます。** 同点人数の全チーム一覧は[確認用の表](結果/確認用_チーム別同点人数.csv)、各セルは[希少24人の表](結果/確認用_希少24人.csv)で確認できます。

1回目の希少平均点は `0.014934210526315791`。そこから得られる人数配置102通りと、その根拠は前の本戦102配置の検証（手元の記録）を引き継いでいます。各チーム0〜2人、対象全体で11人以下、保存した1回目のCSVが実際の提出内容と一致すること、採点方法が同じであることが前提です。【共有された公式結果・配布条件・公式コード】

## 2 仮説

全体は、初回のGen-LRAからseo-02へ変えることで、別の見方が本戦でも役立つかを調べます。seo-02は加工データへの近さと背景データへの近さを比べ、近い1・3・7・15人の見方をまとめます。バトルに使ったコードを変更せず、MIA部分だけを呼び出しました。

加工7案 × 20組の模擬比較では、seo-02の平均は0.1781、seo-01は0.1608でした。一方、加工15案 × 1組ではseo-01が上でした。前者は似た加工案を多く含み、Gen-LRAとの直接比較でもありません。今回の本戦で高得点になる保証ではありません。【保存済みの本戦加工バトル】

希少は、前の検証どおり、**元の2回目の設計からチーム25だけ同点人数を14人→21人に変更**しています。21人の内訳は未確定11人と既知非会員10人です。他の21チームは元の2回目の設定を維持します。

## 3 分析方法

作成処理と検査処理を分け、検査が成功した実CSVだけを完成版の保存先へ移しました。既存の提出物・設定・検証記録は変更していません。

| 安全確認 | 結果 |
|---|---|
| 配布入力、初回CSV、検証済み設定、攻撃コードの変更有無 | 保存済みの照合値と一致 |
| 希少24人 × 22チームの528セル | ID、チーム番号、0.4／0.1、同点人数が全て一致 |
| 希少候補が1人または2人の全組合せ | 各チーム66通り、合計1,452通りを確認 |
| 別々の採点方法による照合 | 公式コード、別ライブラリ、分数計算が一致 |
| 1回目の点数から人数配置を再計算 | 保存済みと同じ102通り |
| 保存したCSVから2回目の点数を計算 | 102通り全てを区別可能 |
| 全体用の値を変えても希少点が同じか | 102配置 × 22チーム、2,244件で確認 |
| 列の入替、旧設定、候補漏れ、不正値などを故意に混入 | 20種類全てを検出して停止 |
| seo-02を独立に再計算 | 全22列が保存した手法出力と完全一致 |
| 公式MIA形式、全行・全列、欠損・重複・値域 | 全て成功 |

人数配置どうしの点数差は最小 `1/936000`、約0.000001068です。公式採点と分数計算との差は最大約0.00000000000000000347でした。保存後の小数値でも読み分けられることを確認しています。【実CSVを用いた検証】

作成時には全体用の上限値でごく小さな小数計算誤差を検出し、完成版の保存を停止しました。数学的に同じ式を整数係数で計算するよう修正し、検査側は分数で独立に計算して、全項目をやり直しています。希少の値は文字列の `0.4` と `0.1` に固定しています。

検査記録は[検証結果](結果/検証結果.json)、入力の照合値は[入力SHA256](結果/入力SHA256.json)、完成ファイルの照合値は[出力SHA256](結果/出力SHA256.json)にあります。実行環境と所要時間は[実行記録](結果/実行記録.json)を参照してください。

## 4 結論

**今回のF_miaは、全体の手法をseo-02へ切り替えながら、希少の2回目の人数特定を続けられる形で完成しています。** 保存CSVから計算した102通りの対応表も[結果フォルダ](結果/2回目の点数と人数102通り.json)へ固定しました。

初回と今回の非希少上位20人の共通人数は、チームごとに0〜10人、平均3.64人でした。計算方法だけでなく上位候補も変わっています。これは正解率ではありません。同点の表示順だけID順にそろえた比較で、提出値の同点は崩していません。【実データ上の順位比較・正解未使用】

実際の本戦の所属は未公開なので、実得点や今後の全ケースの成功を保証するものではありません。提出後はMIA全体の点数・チーム別評価帯を初回と比較し、希少は詳細結果の点数から人数を読み取ります。

### 提出と結果確認で使うもの

1. MIAには、このフォルダの `結果/F_mia.csv` をそのまま使います。表計算ソフトなどで保存し直さず、提出用ZIPに組み込む際も同じファイルか照合します。ZIPには別途用意する `F_aia.csv` と `token.txt` が必要です。
2. 採点後は、画面で丸められた数字ではなく、2回目の `detailed_results.html` を保存します。
3. [結果読取.py](結果読取.py) はHTML内の点数が102通りのどれか1つに一致する場合だけ人数を返します。一致しない・複数一致・保存済みの1回目の結果だった場合は停止します。最も近い点数へ無理に当てはめません。
4. 人数を確認してから3回目の設定を作ります。今回の処理は、次回CSVの自動作成や大会への提出を行いません。

結果読取についても、全102点数、誤った値、重複候補、HTMLの読み取り、1回目の結果の取り違えを確認しました。[確認記録](結果読取の検証.json)

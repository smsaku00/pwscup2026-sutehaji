# 第3回MIAの作成と独立監査

## 前提

2026年10月8日のユーザー指示に基づき、第3回のF_miaを作成した。採用内容は、希少の固定5bit方式、全体のGen-LRA7＋非会員較正500＋他チーム補正0.1、希少人数0の対象の希少24行を0とする修正。自チームは28、攻撃対象は22チーム、行はB_selfの1,049人。【ユーザー指示・配布データ】

第1・2回の公式平均点と保存した提出設定から、Team6・11・17は希少各1人、Team10・16・25は各2人、他16対象は0人と導出されている。共有条件と過去の実提出設定が保存物に一致することを前提に、この人数を用いる。本番の個人所属正解はまだ未知で、作成・監査に使っていない。【公式結果からの条件付き導出】

本番B_selfと自チームの公開AIA課題を公開7属性で突合すると、既知非会員163人（非希少150人、希少13人）。全希少は24人、そのうち未知候補は11人。残る未知通常候補は875人。A_bgは5,143人。過去の配布物・提出物・実験記録は変更しない。【配布データ】

## 仮説

希少は各候補に5bit符号を割り当て、5回の固定質問で所属を特定する。1人チームは11人の単独符号、2人チームは55組の各bit人数和（0・1・2）を用いる。人選は公式の回答に依存せず、第3〜7回を事前に固定する。各チームの人数回答は公式希少平均点から復号する。【固定符号の組合せ計算・公式採点】

全体は、Gen-LRA7のスコアを対象別の既知非会員スコア分布と比較し、県・性別の偏りを較正する。さらに他21対象での順位中央値を0.1だけ引く。この方式の本戦での改善量は未確認であり、今回の計算・形式の監査と、未知の本番正解に対する性能は区別する。【過去の公開正解による比較・今回の仮説】

## 分析方法

### 実回答の構成

`結果/F_mia.csv`はrecord_id列＋22対象列。IDは0〜1048、列順は本番mia_columnsの自列28を除いた順序。

| 行の種類 | 付ける値 |
|---|---|
| 未知通常875人 | 最終順位から0.6超〜0.9へ単調変換 |
| 既知非会員の非希少150人 | 全22対象で0 |
| 希少人数0の16対象の希少24人 | 全24行を0 |
| 希少探索6対象の希少24人 | 固定質問・人数調整に従い0.4または0.1 |

0にする16対象はTeam0・1・2・3・4・5・7・8・9・12・13・14・15・22・26・27。計384セル。

### 希少：第3回の固定質問

全6対象で、未知候補 **115・169・264・383・462** を高側へ選ぶ。追加する既知非会員は、元から確認済みの希少非会員13人のID昇順から取る。

| Team | 希少正解人数 | 高側総数 | 追加する既知非会員ID |
|---|---:|---:|---|
| 6 | 1 | 6 | 126 |
| 10 | 2 | 7 | 126、136 |
| 11 | 1 | 7 | 126、136 |
| 16 | 2 | 11 | 126、136、271、273、317、440 |
| 17 | 1 | 10 | 126、136、271、273、317 |
| 25 | 2 | 12 | 126、136、271、273、317、440、480 |

選んだ候補と追加した既知非会員が0.4、それ以外の希少行が0.1。既知非会員13人を、この6対象でも一律0にすると復号用の設定が壊れるので、その処理は行わない。高側総数と既知の希少正解人数の組合せにより、Team10・11は追加人数が同じ2人でも点数が異なる。

### 固定した第3〜7回の人選

| 提出回 | 6対象共通の高側候補 |
|---|---|
| 3 | 115、169、264、383、462 |
| 4 | 47、115、304、462、675 |
| 5 | 47、90、264、462、495 |

毎回の候補は5人、追加人数も各対象で1・2・2・6・5・7人のまま。11単独符号と55ペアの5成分人数和がすべて異なることを独立に確認した。全6対象の合法配置2,494,800通りに対する保証は、各対象の全候補の一意識別と毎回の人数復号の合成による。全配置を直接総当たりしたとの記録ではない。

陽性総数n、高側総数M、高側陽性数hの希少TPRは `(24-n)*h/[100*n*(M-h)]`。陽性のある6対象を平均し、他16対象はNaNとして除外する。全216回答の平均は異なり、最小差は1/54,000。実運用では詳細結果の生の `mia.tpr_rare` を使う。小数4桁だけの画面表示から特定しない。

### 全体：順位の作り方

1. 公開7属性age・SBP・TG・HDL・ALT・sex・prefectureでGen-LRA7を計算する。TG・ALTはlog1p、数値尺度はA_bgの変換後IQR/1.349、rho=0.98、数値5次元の帯域、近傍10行。B_selfのtimeや転帰を推定特徴に使わない。
2. 対象自身のAIA課題を除き、自チーム28を含む他22チームの公開AIA課題7,172行を既知非会員の較正標本にする。背景A_bgへ追加する方式ではなく、非会員スコアのCDFを較正に用いる。
3. 県・性別群で、`(群人数*群CDF+500*全体CDF)/(群人数+500)`を計算する。標本0の群は全体CDF。外端・較正同値は`0.999*較正値+0.001*元スコアの平均順位/1049`で扱う。元の真の同点はIDで破らない。
4. 通常875人内で平均順位/875へ変換し、自対象を除く他21対象の中央値を0.1引く。
5. 最終値の最小順位を用い、`0.6+0.3*最小順位/875`へ変換する。真の同点は維持する。希少と通常をまとめて再順位化しない。

この値域では、通常875人中にFPR1%を超える十分な非会員があり、全体TPR@1%は希少行に達する前に決まる。第1回の通常順位との全体TPR比較が可能。AUCと総得点は希少変更の影響も受ける。

### 作成と監査の分離

作成器は固定hashを確認した既存core/calibrateを使う。全体監査器はその関数をimportせず、距離・混合密度・CDF・順位・他対象補正を独立に実装し、全22対象を再計算する。希少監査器は作成器・生成設定を正解としてimportせず、原入力のDecimal照合、合意した固定質問、公式score_miaと公式平均関数で照合する。統合監査器は公式validate_mia_submissionに加え、自己列、完全な列集合、行順、有限値などを独自に厳格確認する。

| 確認 | 結果 |
|---|---|
| 公式MIA形式 | 1,049行・22対象、合格 |
| 全体の独立再計算 | 通常19,250セルの提出値・最終順位が完全一致 |
| 既知非希少150人 | 3,300セルがすべて0 |
| 希少設定 | 全528セル一致、うち384セルが0 |
| 固定5bit | 11単独・55ペアの衝突0 |
| 公式採点・集約 | 個別78ケース・平均216ケース一致 |
| 実CSVの希少採点 | 単独・ペア198ケース一致 |
| 非希少変更との隔離 | 198ケースで希少点不変 |
| 意図的な誤り | 全体6種類・希少10種類・統合28種類を検出 |
| 同じ入力からの再作成 | F_miaなど8ファイルがバイト一致、計算配列9種類が完全一致 |
| 公式採点からの復号 | 無作為100配置・各対象の全単独/ペアを含む198配置で正しい9人と所属外2人を特定 |
| 途中結果の復号 | 400履歴で正解候補を保持し、次の固定質問・追加人数も一致 |
| 不正な復号入力 | 非有限値・矛盾・所属重複など13ケースを拒否 |
| 回番号付き入力 | 100通りの引数順変更で同じ正解、途中4ケースも一致。重複・欠け・範囲外など14種類を拒否 |

全体の独立計算の生スコア最大差は4.44e-15、較正値最大差は2.57e-14。最終提出値・順位差は0。独立距離・積和の順序による微小差は提出順位へ影響しなかった。入力と過去提出物の保存hashも照合した。

初回希少監査では、CSVの17桁文字列表現0.10000000000000001/0.40000000000000002をDecimalで直接比較して誤検出した。公式と同じfloatで0.1/0.4へ厳密一致することを確認し、監査器を修正した。候補CSVは変更せず再監査に合格。初回FAIL記録も保存している。

### 再実行・結果読み取り

実行環境はルート`.venv/bin/python -B`、Homebrew Python 3.12.15。依存や古い実験コードは変更していない。作成器は既存の出力先への上書きを拒否し、新しい`--output-dir`のみ受け付ける。入力・参照コードは`input_pins.json`で固定する。

採点後は、結果読取器の`--round-means`へ`3=<第3回の生点数> 4=<第4回の生点数> …`の形式で渡す。回番号で並べ替え、第3回からの途中の回の欠け・回番号の重複・範囲外を拒否する。従来の`--means`は互換用に残すが、回番号付き入力を推奨する。矛盾や点数表への不一致を強制的に丸めて処理しない。

数字だけから、正しい提出回の点数かどうかを常に判定することはできない。具体的には、第4回と第5回、第6回と第7回をそれぞれ入れ替えると、固定符号に90↔304、115↔264、169↔383、495↔675の対応が生じる（47・76・462は不変）。この取り違えは100合法配置すべてで受理され、99配置で異なる所属へ復号された。回番号付き入力は引数順の取り違えを防ぐが、誤った回番号を点数へ付けた場合は検出できないことがある。実提出CSV・採点原本・回番号の対応を照合してから入力する。この制約と具体例は復号監査に保存した。【固定符号の独立検算・公式採点による模擬配置検査】

## 結論

合意した第3回MIAを作成し、公式形式・独立数値再計算・希少符号・平均点復号・改変拒否・再作成一致を確認した。使用するCSVは`結果/F_mia.csv`、SHA-256は`6ca9604a8936fb47255ae0bd05c9f3958368f0e196bc2af258f8255cf39c08eb`。

## 2. P01の動き

P01はTashiroの `stable_matching/sex_quota/long75` を提出用に移植した方式。元の分析プログラム全体を実行せず、公開入力だけを使う選別関数を利用する。

1. 年齢・SBP・TG・HDL・ALTの5属性を使う。TGとALTはlog1p変換し、公開背景の四分位範囲で距離を標準化する。
2. challengeの各行とCの各行を比較し、**同じC行の中で差が小さい2属性**の平均二乗距離を取る。使う2属性は比較する組合せごとに変わる。
3. **性別は一致必須。都道府県はP01の距離に使わない。** 地域を加工している可能性があっても、数値属性の対応を探せるようにする。
4. 同じchallenge行から公開背景への部分距離と比べ、Cへの近さがどれほど例外的かを評価する。これは標的である確率ではない。
5. 部分距離の12番目までの近傍を候補とし、境界で同距離の行も含める。部分距離の同点には5属性全体の距離を微小な補助量として使う。
6. 性別ごとに75%の人数を選ぶ。**選んだchallenge行どうしで同じC行を重複利用しない**割当を計算する。割当は選別のための仮説であり、実際の人物対応の証明ではない。
7. **選んだ245行には9.5年、残る81行には0年を回答する。P01の回答値にはCのtimeをコピーしない。**

**S4との大きな違いは、距離・選別・回答値の3点。** S4は5属性とカテゴリを使う最近傍・背景距離比で選び、選んだ行に最近傍Cのtimeを返す。P01は部分2属性と対応の競合を使って選び、選択行には一律9.5年を返す。

9.5年は真のtimeが9～10年なら許容誤差±0.5年に入る。0年も真のtimeが0～0.5年なら的中し得る。**0年は棄権記号ではなく数値回答であり、81行が対照だと確認したわけでもない。**

### P01を試す根拠と限界

予備戦の公開正解による18対象の比較では、S4系の比較基準の一般群R平均が0.032560、P01が0.111736だった。改善13対象、悪化5対象。部分属性と割当競合を使う候補を試す根拠にはなるが、**本戦の最終得点の予測値ではない**。同じ予備戦データを開発にも利用している。

今回の公開本戦入力では、15チームすべてで245行選択・81行非選択となった。元ソースの予測との一致と、行順を変更した場合の選択の一致も検査した。これらは実装と選択の安定性の確認であり、実際の攻撃性能の確認ではない。

## 3. 残る7チームの具体的な変更

### チーム0・15：回答範囲を広げる

第2回のtimeが0年かつ第1回のtimeが正の行だけ、第1回の回答値を戻す。その他は第2回の回答値を使う。

- **チーム0：161行を復元。正の回答262行、0年64行。**
- **チーム15：153行を復元。正の回答264行、0年62行。**

復元する行が標的と分かったわけではない。両チームは第1回に正の得点があり第2回は0だったため、回答を絞った影響を比較する。第1回の326行全体に戻す方式でもない。

### チーム3・4・11・14：部分対応でtimeを補完する

第2回の回答値を基準とし、N2の背景補正指標が0.3未満の行には対応候補Cのtimeを回答する。N2は全5属性と数値属性を1列ずつ外した比較の計6通りを使い、性別・年齢層別の背景近接で偶然の対応を補正する。

**P01の「組合せごとの部分2属性」と、N2の「1属性ずつ除外する6通りの比較」は別の方法。** また、N2の0.3は選別指標の閾値であり、標的確率30%という意味ではない。

| チーム | 第2回の基準 | 補完対象行 | 実際に回答値が変わる行 |
|---|---|---:|---:|
| 3 | N3：性別を使う5近傍時間窓 | 99 | **93** |
| 4 | S3：Shadow時間窓 | 116 | **60** |
| 11 | S3：Shadow時間窓 | 103 | **103** |
| 14 | N3：性別を使う5近傍時間窓 | 110 | **36** |

補完対象でも新旧の値が同じなら変更行に数えない。4チームとも最終的に326行すべてに正のtimeを回答する。

**11チームは、過去S4が除外した81行を0年にする方式を今回採用しない。** 公開背景で作った同じ16問題の比較では、一般群R平均はS3単独0.679249、S3＋S4選別0.642539、S3＋部分対応補完0.720768だった。後者はS3より12問題で改善し4問題で悪化したため、今回の候補とした。

この模擬Rは標的の正解率や11チームの公式予想点ではない。実際の加工・希少群・φを再現しておらず、P01の予備戦比較とも評価条件が違う。

### チーム9：N9に14行を追加する

第2回N9の326行を基準とする。N2の背景補正付き部分対応で、C行を最大2回まで使うN4割当を計算する。**第2回が0年で、N4が正のtimeを提案した14行だけ追加する。**

追加するchallenge_row_id：

`10, 30, 50, 58, 118, 157, 166, 170, 221, 224, 239, 247, 289, 293`

既存の245行の正の回答は今回の候補では同じ値とし、正の回答は259行、0年は67行となる。N4の326行全体への置換ではない。**この14行は確定標的でも希少13人でもない。**

第2回の最終得点0.746201は行ごとの正解率ではない。追加する標的的中と対照的中のバランスによって、新しい最終得点は上下する。

## 5. 第3回の結果を受け取ったら

**主な比較対象は、各チームの `aia_per_target` と、その22チーム平均である `aia_power`。** 一般群の `r_time_all` だけで最終的な良し悪しを判断しない。最終得点には一般群・希少群の結果と相手チームごとのφが反映される。

1. 各チームの第3回得点を、そのチームの第1・2回の最高点と比較する。
2. 改善した候補は選択率・部分属性・回答時間などを次回の比較軸にする。悪化した候補は原因を検討し、別候補も試す。
3. 第3～7回のCSVとチーム別得点を対応づけて保存する。
4. **第8回は第1～7回の最高得点を出した326行の回答ブロックをチーム別に組み合わせる。** 行ごとに正解が分からないため、異なる回の回答を行単位で無根拠に混ぜない。

主催者がチーム別最高点を自動で合算するわけではない。第8回には実際に組み合わせた提出を作り、最終的に採用する提出を指定する必要がある。

今回は複数チーム・複数行を変更する。全体のp_m・p_cの変化は合計の診断には使えるが、特定チームや特定行の標的・対照判定にはそのまま使えない。

## 6. 再生成方法

必要環境：Python 3.10以上、numpy、pandas、scipy。

```text
python -m pip install numpy pandas scipy
python PWSCup2026_T28_round3_AIA.py --data-dir "<公開本戦データのフォルダ>" --a-bg "<本戦公開A_bg.csv>" --round1-csv "<第1回の実提出F_aia.csv>" --round2-csv "<第2回の実提出F_aia.csv>" --output-dir "<新しい出力フォルダ>"
```

`--data-dir`には `mia_columns.json`、各相手の `C_k.csv` と `aia_challenge_k.csv` が必要。背景は本戦の5,143行、Cは1,049行、challengeは326行を前提とする。

GitHubの同じフォルダ構成を保って使う場合、第1回の回答は `../一回目/F_aia.csv`、第2回は `../第2回/F_aia.csv` を既定値として読む。公開データと背景の位置が異なる場合は引数で指定する。

**第1・2回の実提出回答は明示的な基準入力として必要。** 今回のコードはS3モデルを再学習せず、実際に第2回に提出したS3の回答に補完を加える。相手の正解データを使うこととは異なる。

再生成すると `F_aia.csv` と `execution_record.json` を保存する。既存出力を置き換える場合だけ `--overwrite` を指定する。コードから競技サイトへの提出やGitHubへのアップロードは行わない。

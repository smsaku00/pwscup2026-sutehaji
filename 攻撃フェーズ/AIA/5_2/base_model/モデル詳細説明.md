# 5_2の基準モデル：LR10＋希少群の弱い補正

Team28 / zhang / 2026-10-10。方式名 `lr10_75_rare_soft`。

この文書は5_2で内部的に再生成する基準モデルの記録。以下の基準回答件数・予備選評価は、小人数グループを分割する前の方式についての値である。**実際の提出には[5_2](../README.md)を使用する。旧版の回答CSV・ZIPは削除済み。**

## 1. 何を推測しているか

この方式は、最初に「その対象者が、攻撃する相手の元コホートに所属していそうか」を推定する。所属らしい人に9.5年を答え、その他には11年を答える。対象者の年数を連続値として回帰する方式ではない。

9.5年なら、真のtimeが9.0〜10.0年のときに±0.5年の正解になる。11年は配布データの真のtime範囲0〜10年から外れるため、必ず外れる数値回答になる。予備選で、この所属による選別と固定年数の組合せが比較的強かった。

理由はAIAの採点にある。標的で年数を当てるだけでなく、対照に対して当たる割合を抑える必要がある。所属推定が役立てば、対照に11年を答えることで標的と対照の正解率の差を作れる。ただし、所属推定を誤って標的を外すと、その人の正解機会も失う。

## 3. 距離の準備

臨床4属性は `SBP, TG, HDL, ALT`。TGとALTは `log1p` で変換する。各属性の尺度には背景A_bgの四分位範囲IQRを使い、IQRの下限を `1e-5` とする。年齢を含む照合では、背景の年齢IQRで年齢を割る。

照合先は同じ性別のCまたは背景に限定する。

- 4属性距離：尺度を合わせた臨床4属性のユークリッド距離。
- 5属性距離：同じ臨床4属性に年齢を加えたユークリッド距離。
- 部分2属性距離：1つの照合先レコードについて、5属性の二乗差の小さい2つを選び、その平均の平方根を取る。その後、照合先レコードの中で最小値を取る。
- 属性ごとの距離：各臨床属性について、同じ性別の照合先で最も近い値との絶対差。

部分2属性距離は同じ照合先行の2属性を使う。一方、属性ごとの距離は属性ごとに別の行が最近傍になってよい。加工によって属性間の組合せが崩れていても、値の残り方を拾う目的で両方を用意する。

## 4. 所属推定に使う35特徴量

以下で `d_C` はCとの距離、`d_B` は背景との距離。最近傍距離を大きさのまま渡すのではなく、多くは `-log1p(d)` または距離比へ変換する。

| 分類 | 特徴量 | 個数・計算 |
|---|---|---|
| Cとの近さ | `member_near4`, `member_knn4`, `member_near5`, `member_partial2` | 4個。4属性最近傍、4属性の5番目の近傍、5属性最近傍、部分2属性最近傍の `-log1p(d_C)` |
| Cとの近さの順位 | `rank_member_near4`, `rank_member_near5`, `rank_member_partial2` | 3個 |
| Cの属性値との近さ | `c_sbp`, `c_tg`, `c_hdl`, `c_alt` | 4個。属性別距離の `-log1p(d_C)` |
| 背景との近さ | `bg_near4`, `bg_knn4`, `bg_near5` | 3個。対応する `-log1p(d_B)` |
| 背景との近さの順位 | `rank_bg_near4`, `rank_bg_knn4` | 2個 |
| 背景の属性値との近さ | `bg_sbp`, `bg_tg`, `bg_hdl`, `bg_alt` | 4個 |
| C対背景の差 | `contrast_near4`, `contrast_knn4`, `contrast_near5` | 3個。`log1p(d_B)-log1p(d_C)` |
| 属性別の距離比 | `ratio_sbp`, `ratio_tg`, `ratio_hdl`, `ratio_alt` | 4個。`log((d_B+0.001)/(d_C+0.001))` |
| 距離比のまとめ | `col4`, `col2`, `col1`, `col4_min` | 4個。4属性の平均、強い上位2属性の平均、最大、最小 |
| 差・距離比の順位 | `rank_contrast_near4`, `rank_col4`, `rank_col2`, `rank_col1` | 4個 |

順位は対象の326行の中で計算し、同順位には平均順位を使い、326で割る。性別ごとの順位ではない。モデル入力はこの表の35列だけで、列順は `round5_engine.py` の `COLS` に固定している。

`feature_engine.py` は元の検証済み特徴量計算を保持しており、上表以外の診断用列も計算する。それら、他Cとの距離・生の年齢・生の性別・team ID・row IDは、この2つのLRには入力しない。row IDは同点処理と出力の対応づけに使う。

## 5. 2つの所属推定モデル

35特徴量に `StandardScaler` を適用してから、ロジスティック回帰で所属ラベルを学習する。Scalerは学習データだけでfitする。

| モデル | パラメータ | 役割 |
|---|---|---|
| LR10 | `C=10`, `max_iter=1500` | 各性別の上位75%を選ぶスコア |
| LR0.04 | `C=0.04`, `max_iter=1500` | 希少候補の群内補正に使うスコア |

どちらもscikit-learnの既定のL2ロジスティック回帰・lbfgsを使う。Cが大きいLR10はLR0.04より正則化が弱い。クラス重みは設定しない。

2つのモデルを使い分ける理由は、基準の選別には予備選で強かったLR10を使い、群内補正には前段の希少群実験から固定したLR0.04を使うため。確率出力が本戦の真の所属確率として較正されているとは保証していない。

## 6. 基準回答：性別ごとの上位75%

性別ごとにLR10の所属スコアが高い順に並べ、人数を `ceil(0.75 × その性別の人数)` として選ぶ。スコアが同じ場合は `challenge_row_id` が小さい人を先にする。

```text
選ばれた人 → 9.5年
選ばれない人 → 11年
```

真の標的数が163人だから163人だけ選ぶ、という制約は入れていない。75%という広めの選別は、標的を外す損失と対照へ当てる損失の両方を予備選で比較した設定である。

今回の本戦22標的で、補正前は合計5,390行が9.5年、1,782行が11年だった。

## 7. 希少候補26人の選択

別のRandom Forestで、次の6値から `is_rare` を学習する。

`age, SBP, log1p(TG), HDL, log1p(ALT), sex`

設定は以下。

```python
RandomForestClassifier(
    n_estimators=180,
    min_samples_leaf=3,
    max_features=1.0,
    class_weight='balanced_subsample',
    random_state=20261010,
    n_jobs=2,
)
```

各標的の326行を希少スコアが高い順に並べ、上位26人を希少候補にする。同点ならrow IDの小さい人を先にする。26人は真の希少26人を知っているという意味ではなく、実験で固定した候補人数である。

## 8. 「ペア」は真の組を特定したものではない

希少候補26人の中だけで、次のキーが同じ人をまとめる。

`(prefecture, sex, floor(age / 5))`

例えば年齢50〜54歳は同じ5歳帯になる。1人だけの群、奇数人数の群は変更しない。2人・4人・6人など偶数人数の群だけを補正する。

この集合が、運営の実際の標的・対照の組と一致する保証はない。推定希少候補の誤分類も起こる。したがって、全員を無条件に1対1へ強制する処理は使っていない。

## 9. 弱い補正の数式

群の各人のLR0.04スコアを `p_i` とし、`[1e-6, 1-1e-6]` にclipしてからロジットにする。

\[
z_i = \log\frac{p_i}{1-p_i},\qquad
\sigma(z)=\frac{1}{1+e^{-z}}
\]

全員に共通のオフセットδを入れたとき、群の確率平均が0.5となるδを探す。

\[
\frac{1}{|g|}\sum_{i\in g}\sigma(z_i+\delta)=0.5
\]

探索はδの範囲 `[-30, 30]`、二分探索60回。そのδを全部ではなく半分だけ適用する。

\[
\tilde p_i=\sigma(z_i+0.5\delta)
\]

`tilde_p_i < 0.5` の人を11年にする。もともと11年の人は11年のまま。この補正で11年から9.5年へ戻すことはない。

例えば、2人の元スコアが約0.52と0.80なら、半分の補正後は約0.429と0.735となる。低い側は11年に変わり、高い側は元の回答を保つ。

半分だけなので、補正後に必ず半数が標的側になるわけではない。全員が0.5以上に残る群も、全員が0.5未満になる群もありうる。確率順序は保ち、群内の基準だけを動かす。

最後に、希少候補でない行が基準回答から変わっていないことをassertで確認する。

## 11. 予備選での評価

対象コホートの正解を学習から外し、残り20コホートで所属と希少らしさを学習して対象へ回答した。回答の生成後に対象自身の公開正解で採点した。

評価は標的・対照それぞれ163人、希少の標的・対照それぞれ13人。timeの誤差が0.5年以内なら正解。

全体の正解率を `p_m, p_c`、希少の正解率を `p_mr, p_cr` とすると、比較で使った指標は次の通り。

\[
R_{all}=\operatorname{clip}_{[0,1]}\frac{p_m-p_c}{1-p_c}
\]

\[
R_{rare}=\operatorname{clip}_{[0,1]}
\frac{p_{mr}-p_{cr}-1.64\sqrt{p_{mr}(1-p_{mr})/13+p_{cr}(1-p_{cr})/13}}{1-p_{cr}}
\]

比較値は各標的の `max(R_all, R_rare)` の平均。難易度差し引きφはこの表では0。分母が0に近い場合は実装で下限 `1e-9` を使う。

| 方法 | 加工済み18標的 | 全20標的 |
|---|---:|---:|
| LR10・補正なし | 0.162984 | 0.206215 |
| 第5回方式 | **0.175711** | **0.218155** |
| 補正による平均差 | **+0.012727** | **+0.011940** |

加工済み18標的はコピー標的1・2と予備選自チーム5を除く。20標的は自チーム5だけを除く。

18標的では補正により7標的で改善、8標的で悪化、3標的で同点。20標的では9改善・8悪化・3同点。平均は改善しているが、補正が全標的に有利なわけではない。

既存の予備選Team05回答とこの第5回方式の、標的ごとの最高値を選んだ参考平均は、18標的0.191887、20標的0.272698だった。これは提出後の得点を見て既存回答も残す運用の比較であり、第5回単独の平均ではない。

第5回を選ぶ前には未提出方式を含む70候補を比較し、3回分の全54,740組を評価した。第5回はその組合せで選んだ所属推定側の案である。候補選択に予備選全体の結果を使っているため、上の値は方式選択から独立した汎化性能の保証にはならない。

本戦では相手の加工や背景の分布が予備選と異なる可能性がある。また、本戦の正式得点では標的ごとの難易度φの差し引きがある。上表の値を本戦の得点として扱わない。

## 3. 固定した方式

`results_mock/frozen_plan.json` は今回の予測・採点より前に保存しました。ただし、このベンチマークの過去結果や先行する会話は既に参照しているため、未知データに対する事前登録試験ではありません。

### 希少候補モデル

既存 `希少候補の学習.py` と同じ特徴・HGB設定を実装しました。特徴はage・SBP・log1p(TG)・HDL・log1p(ALT)・sex。設定は140反復、最大葉15、最小葉35、L2=5、seed=20261007です。

ただし、今回の**模擬実行**では、自チームBの神奈川県以外662行・希少10行だけで学習しました。課題の標的は全員神奈川県なので、その標的レコードを学習に入れません。これは元の公式予備戦7foldの再実行ではありません。上位26候補中の既知の希少標的は各パネル2〜3人で、分類器の学習条件は弱いものです。対照希少が不明なため、希少全体の適合率・再現率は出しません。

`--mode official` は元の方式と同じ `GroupKFold(7)` を使い、各評価コホートのis_rareを学習に入れません。membershipの正解labelは採点専用です。

### 基準回答と候補フィルタ

3種類の標的らしさを、公開QI・C・BGから計算します。TG・ALTをlog1p変換し、BGのIQRで尺度をそろえます。

| スコア名 | 処理 |
|---|---|
| `near4` | 同性の同一C行への臨床4属性の最近傍距離 |
| `col4_simple` | 各列でCとBGの最近値までの距離比の対数を取り、4列平均 |
| `col2_simple` | 同じ列別証拠の強い2列を平均 |

**これらは新たな簡易比較方式で、既存P01・k1 all4・k1 top2の完全再現ではありません。** 原本の数値と直接優劣比較しません。

基準回答は性別ごとにスコア上位75%（切上げ）へ9.5年、残りへ0年または11年です。全て同じ値で的中するとは仮定せず、実際のtimeと±0.5年以内かを採点します。onset=0でも早期打切り・死亡等によってtime<10になり得ます。

ペア候補は、県・性別・年齢帯により、(a)全課題の中で2人だけのグループ、または(b)推定希少上位26人の中で2人であり、上位52人へ広げても同じ2人しか残らないグループとしました。26／52は候補抽出の設定であり、模擬の真の希少人数ではありません。

さらに、性別内の順位差が0.25以上で、`near4`と`col4_simple`の示す標的方向が一致した候補だけを修正します。高側は9.5年、低側は棄権値へ変更し、条件を満たさない行は基準のままです。**順位差0.25は標的確率75%を意味しません。**

主条件は模擬生成と一致する10歳帯です。5歳帯は誤った区切りを入れた感度診断として分けます。過去の公式予備戦で5歳帯が有力だったという観測に対する反証ではありません。

## 4. 実測結果

### 4.1 10歳帯では修正対象がなく、回答は変わらない

以下は**模擬15ケースの平均R_all**です。phi控除前であり、希少Rや公式AIA攻撃力ではありません。

| 基準スコア | 基準・0年 | ペア候補修正・0年 | 基準・11年 | 0→11の差 |
|---|---:|---:|---:|---:|
| 同一C行・4属性距離 | 0.029171 | 0.029171 | 0.024665 | -0.004506 |
| 列別近接比・4列平均 | 0.119239 | 0.119239 | 0.114983 | -0.004256 |
| 列別近接比・上位2列 | 0.075998 | 0.075998 | 0.071445 | -0.004553 |

10歳帯では候補段階で0組でした。したがって「高信頼候補への限定で改善した」ではなく、**今回の条件では何も変更できなかった**という結果です。

全グループへ半数制約を強制する比較では、0年の平均R_allは順に0.022055、0.084714、0.070850となり、いずれも基準より低下しました。これも3つの固定Cに対する探索的な結果です。

### 4.2 5歳帯の感度診断：標的同士をペアと誤認

安定した希少候補として2組が抽出されましたが、**どちらも標的2人の組**でした。正しいペアは0組です。

| パネル | 候補のchallenge_row_id | 実際の構成 |
|---|---|---|
| 9503 | 117・91 | 標的・標的 |
| 9505 | 266・167 | 標的・標的 |

2組×3C＝6組合せ／スコアの中で、方向一致と順位差条件を通過したのはnear4で1件、4列平均で3件、上位2列で0件です。通過しても元回答と同じ場合があり、combined候補修正で実際に変わったのは、Zhang06・パネル9503のID91の1行だけでした。**9.5年で正解していた標的を0年に変え、不正解にしました。**

この事例は、「希少候補に絞ってから2人になった」という事実が「標的と対照が1人ずつ」の根拠にはならないことを示しています。

### 4.3 正しいペアが既知でも、向きの推定は別問題

模擬の保存pair_idを使い、正しい組だけが与えられた場合を診断しました。**隠されたpair_idを使用するため実戦で利用できる方式ではありません。** 標的／対照labelはスコアの方向決定には使わず、後から正誤を判定しました。

各方式の総比較数は163組×15ケース＝2,445組合せです。次は順位差・方向一致の条件を通過した組に限った結果です。

| スコア | 通過組合せ | 向きを正解 | 通過後の正答率 | 元BそのものをCにした確認条件 |
|---|---:|---:|---:|---:|
| 同一C行・4属性距離 | 750 | 363 | 48.4% | 100.0% |
| 列別近接比・4列平均 | 796 | 415 | 52.1% | 100.0% |
| 列別近接比・上位2列 | 630 | 340 | 54.0% | 100.0% |

本当に正しいペアを与えても、今回の加工3Cでは通過後の向きが約48〜54%であり、高い信頼性になりませんでした。元BをそのままCにする正の確認条件では通過後100%なので、少なくとも明確に行が残っている状況での照合は動いています。

正しいペア＋今回の信頼条件で実際に回答を変えると、0年の平均R_allはnear4=0.022941、4列平均=0.082974、上位2列=0.069908となり、いずれも基準を下回りました。**ペア特定だけでなく、標的方向を判定する証拠も改善する必要があります。**

### 4.4 0年から11年への置換は、今回は標的側だけを損なった

基準の選択マスクを固定して棄権値だけを変えた15ケース合計で、対照の的中を減らした件数は3方式とも0件でした。一方、0年で偶然正解していた標的をnear4では延べ11件、4列平均では4件、上位2列では5件失いました。これが平均R_allの低下につながっています。

11年はtrue_time≤10・許容差0.5なら必ず外れますが、**誤って対照と判定した標的も必ず外す**ことになります。11年を一律に使うべき、あるいは0年が常に良い、とは結論しません。現在の大会検証器での新規受理試験も行っていません。

## 5. 検証・再現性・限界

11本の単体試験が成功しました。標的希少正解数0〜13×対照希少正解数0〜13の196通りと、追加の無作為100予測について、**保存済み公式採点関数と今回の採点関数が一致**しています。これは公式データの攻撃性能評価ではなく、採点実装の検査です。欠測・負の予測値・列漏えいの拒否、同点を含む行並替不変性、候補不採用時の回答維持も検査しています。

元ZIPから別フォルダへ再抽出・再実行し、`case_metrics.csv`、`summary.csv`、`pair_audit.csv`、`miss_value_contrast.csv`、計画JSON、詳細変更行の6ファイルがバイト単位で一致しました。詳細変更行の原ファイルには真のtimeが含まれるため、配布物には含めません。代わりにtimeを除いた必要な変更行だけを監査CSVに残します。

主な限界は、(1)公式追加実験が未実行、(2)模擬対照の真の希少ラベルが不明、(3)異なるデータ世界のBG、(4)5パネルの個人再利用、(5)3Cが同じ自チームの加工案、(6)模擬学習の希少が10行、(7)順位差が確率として較正されていない、という点です。したがって今回は独立標本としてのBootstrap区間は報告しません。

## 6. 公式予備戦へ進むときの固定手順

`experiment.py --mode official` は、GitHubの `公式データ/予備戦/` をそのまま読みます。自チーム5を除く20対象、さらに1・2を除く18対象を別々に集計します。真の希少ラベルは他foldでの希少モデル学習と採点にのみ使い、membership・onset・time・pair_idは候補選択へ渡しません。

**まず今回の定義を変えずに走らせることを優先**します。公式では「候補が真にmember/controlの1人ずつか」は確認できますが、ペアIDがないので、生成時の本当のペアかまでは証明できません。旧P01／旧all4／旧top2の実回答に修正を重ねる統制比較は、このコードではまだ実装・実行していません。

```bash
# この実験フォルダをカレントディレクトリにする。既存環境を壊さないよう別venvを使う。
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest test_experiment -v

# 実際の公式データで走らせる操作。この成果物作成時には未実行。
python experiment.py --mode official \
  --root /path/to/pwscup2026-sutehaji \
  --out /path/to/local_results/official_pair_run
```

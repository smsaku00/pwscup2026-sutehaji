## 1. 先に固定する方針

- 1回目から有効な回答を確保する
- 定数回答だけ、形式確認だけ、既知非会員の修正だけで提出枠を使わない
- 第4〜7回はMIA・AIAの両方に検証項目を置く
- 過去最高の回答を寄せ集めるだけの提出にはしない
- 予備戦の知見は手法として引き継ぐ
- Team 05の回答、患者ID、32セル等の確定非会員、相手チーム番号は持ち越さない
- 比較相手を事前に指定
- MIAとAIAを同時に変更しても、総得点差を片方だけの効果と説明しない
- 新しい設定はローカルで絞ってから提出する
- 改善が見えない場合、同じ回の目的に沿う代替案を使う
- 8枠を予定どおり消費すること自体は目的にしない
- 第8回を残す
- 第7回までに統合材料を確保し、最終提出を締切当日に持ち越さない
- 【提案】以上は、予備戦の最終統合の効果と、バトルで追加攻撃が新しい弱点を見つけたことを踏まえた配分である
- 本戦での改善量を保証するものとは別

## 3. 各回の具体案

### 第1回：本戦の基準を作る

- MIA：`seo-03-正則化生成比と全体割当` のMIA部分
- AIA：`seo-04-選別最近傍AIA`
- 既存の別々の回答を1回の提出にまとめる
- MIAはCと背景の分布差、AIAは確かな近傍を重視する
- 既存コードは比較の出発点として選ぶもので、全対象での最良とは仮定しない
- ローカル比較：MIAは公式参照MIA、AIAは公式参照1NN・部分対応AIA・全員10年を併記する
- 提出前：本戦の全対象で出力と実行時間を確認
- 基準の選択を変える場合は、その理由と比較結果を先に記録
- 提出後：相手別AIA、MIA評価帯、全体・希少の集約値を保存
- 全体・希少のどちらに伸びしろがあるかを把握する
- 【根拠】9/23の15加工案比較では、選別最近傍を含む追加4攻撃が既存攻撃で見えなかった弱点を見つけた
- ただし直近300組では別の傾向もあり、単一手法への固定は避ける

### 第2回：個人とCの対応を探す

- MIA：`seo-01-近傍対比と条件付時間窓` のMIA部分
- AIA：`seo-01-部分対応AIA`
- 第1回の分布モデルから、近傍や部分的な対応へ攻撃の原理を変える
- 比較：MIA・AIAとも第1回
- ローカルではAIAの独立1NN・TT-02全体対応・容量付き全体割当も同じ課題で比較
- 観察：距離だけでなく、背景に対する相対的な近さ、複数人が同じC行へ集中する程度、丸め・複製の有無を確認
- 次の判断：この方式で伸びる対象は、第6・7回の属性選択や照合の確かさの検証候補にする
- QIが一致しただけで本人や正解timeを確定しない

### 第3回：分布と時間窓を学習する

- MIA：予備戦第7/8回のGen-LRAを本戦入力に対応させる
- AIA：`seo-02-時間窓BoostingAIA`
- MIAの第一候補は全体7属性・希少9属性
- 予備戦の個別回答を再利用せず、本戦のCから再計算
- 比較：MIAは第1・2回、AIAも第1・2回
- MIAは7・9・10属性をローカルで比較し、提出設定を1つに固定する
- AIAはtimeの平均二乗誤差より、±0.5年に入る時間窓と公式の成功度を重視する
- 次の判断：直接照合が弱い対象でも分布学習で改善するか
- MIAの全体と希少で有効な属性が違うか
- 代替：Gen-LRAの旧コードが新環境・本戦入力で検証を通らない場合は、`seo-02-多尺度密度比と差分時間窓` のMIAを使う
- 代替の正則化生成比を「Gen-LRA」と呼ばない
- 【根拠】予備戦第6→7回ではMIA全体TPR・希少TPRがともに改善したが、前処理・制約等も含む提出差である
- 属性数だけの因果効果や本戦での再現を保証しない

### 第4回：希少MIAの制約と、背景との差を学ぶAIA

- MIA：本戦用の制約付き同時確率の「人数条件のみ」を試す
- AIA：`seo-03-Shadow窓順位AIA`
- MIAでは第1〜3回の観測と本戦ルールから、確実に言える条件だけを使う
- AIAでは公開背景から模擬加工を作り、標的と対照の的中差につながる特徴を学ぶ
- 比較：MIAは制約なしの第3回に加え、同じ制約下の重み0・0.5・1をローカル比較
- この回に出す第一候補は重み0
- AIAは第3回の時間窓Boosting
- 制約の適用条件：共有人数の範囲、希少共有の範囲、確定した非会員などについて、本戦の出典と導出を残せること
- 予備戦のグループ分けは流用しない
- 重要：攻撃対象外コホートや非共有への「割り当てない」状態を残す
- 少ない提出対象に全共有者を押し込まない
- 「1人の共有先は最大1つ」も現行仕様との整合を確認してから使う
- 代替：本戦の情報では制約がほぼ対称で有用な順位が付かない場合、MIAは第3回から全体7→9属性を変更し、希少側を固定する比較へ切り替える
- Gen-LRAを使えなければ局所密度比で同じ属性比較を行う
- 次の判断：人数条件に情報があるか、距離を足す前の基準として使えるか
- AIAの模擬学習が実対象にも通用するか

### 第5回：似かたの追加効果を切り分ける

- MIA：第4回と同じ制約に、対応の固有性を重み0.5で加える案
- AIA：`seo-02-多尺度密度比と差分時間窓` のAIA部分
- 固有性とは、あるC行への近さを、他の候補も同じくらい近いかと比べること
- 比較：MIAは第4回の重み0、重み1はローカルの感度確認に残す
- AIAは第3・4回と、同じ近傍を使う「Cの時間窓のみ／背景の時間窓を差し引く」の比較
- 第4回で制約を採用しなかった場合：同じ基準MIAに固有性の項を弱く加える比較にする
- 制約の効果があったとは説明しない
- 観察：希少の上位候補を変えた対象、全体順位への副作用、AIAの標的・対照両方の的中率を残す
- 次の判断：より鋭い確信度が実際の改善につながるか
- 改善が特定の対象だけに集中していないか
- 【根拠】予備戦の公開正解による再採点では、人数条件のみで合計0.377872、固有性の重み1を加えて0.383428
- 追加分は約0.0056で、改善と悪化が相殺している
- 重み1の一括採用より、弱い追加を検証する理由になる

### 第6回：属性変更への頑健性を試す

- MIA：`seo-04a-多重縮小生成比MIA`
- AIA：`TT-01-部分属性照合` を基に、使用属性を変えたときの安定性を確認する案
- TG・ALTの尺度、県や性別の一致条件、一部属性への依存を点検する
- 比較：MIAは第1回の単一正則化モデル、AIAは第2回の部分対応
- ローカルで1項目ずつ除いた結果も比較し、使う属性と重みを提出前に固定する
- 基準：Cの数行・数属性が変わっただけで上位順位や時間窓が大きく変わる場合、その変化を改善とは数えない
- 次の判断：設定や属性を少し変えても改善が残るか
- 似たモデルを増やしただけの見かけの多数決になっていないか
- 【根拠】直近の加工候補では少数のTG・age・time交換でも攻撃の反応が変わった
- 加工候補の平均成績が良いことは、この攻撃自体の本戦性能の保証とは別

### 第7回：不確かな判断を抑える新方式

- MIA：判断根拠の弱い希少候補を同点にまとめる案
- AIA：照合の確かさに応じて、近傍timeと背景差の時間窓を切り替える新方式
- 第8回の単純な対象別統合とは別の、回答を生成する規則の実験にする
- MIA比較：第5回または第6回のうち、事前に指定した1つの元回答
- 候補と入力情報をそろえ、希少の順位付けだけを変更
- 全体MIAへの影響も評価
- AIA比較：第2回の照合系と第5回の差分時間窓
- 近傍間隔・C/背景の距離比・属性を変えたときの一致度から切替条件を決める
- AIAの切替閾値は調整用データで決め、別の評価条件で確認してから固定する
- 未知の標的・対照ラベルや、隠された希少属性で切り替えない
- 代替：新方式の検証が間に合わなければ、MIAは検証済みの同点化候補、AIAは第2回の対応法から容量付き全体割当へ変更する案を比較候補にする
- 新しい検証価値がなければ枠を温存する
- 次の判断：強い誤判定を減らすことで、低FPRのMIAと対照補正後のAIAが改善するか
- 同点化は自動的に得とは別
- 同点群は公式ROCでまとめて扱われ、先頭の正解を強調する効果も薄まる
- AIAの時間の単純平均も、両方の正解窓から外れる可能性があるため採用しない

### 第8回：本戦の実績を使って最終回答を作る

- AIAは対象単位の回答ブロックを統合し、MIAは実績を確認できる回答行列を基本に選ぶ
1. AIAは第1〜7回の本戦の相手別得点が最高の回を、相手ごとに選ぶ
- 選んだ回の全challenge行をそのまま使い、行ごとに正解を推測して混ぜない
- 公式結果が補正前か後かを確認し、同じ定義で比較
- 同じ対象ではφが固定なので、補正前の大小は補正後に逆転しないが、補正後0の同点は起こる
2. MIAの相手別1〜4帯は全体TPRの粗い情報であり、希少を含む最高列を特定できない
- 原則は、本戦でMIA成績が最も良いと確認できた回の行列全体を採用する
- 総得点から対象別AIA平均を引く場合は表示丸めの誤差区間も残し、区間が重なる回を確定順位にしない
3. MIAの列差し替えや全体・希少の再混合を行うなら、既に公式採点した組合せか、採用理由と不確実性を説明できる範囲に限定する
- 帯1を0点、帯4を満点と置いて列を選ばない
4. 保存済みCSVからIDで統合し、元回答・選択表・統合結果のハッシュを残す
- 全体割当型AIAを統合時に再実行すると回答が変わり得るため、採点済みブロックをコピーする
5. 第8回を採点後、公式総得点で過去の有効提出と比較
- 悪化した場合は過去の最良提出を最終採用する
- 最新版を無条件に採用しない
6. 締切前に、採用する提出ID・採点完了・リーダーボード掲載の3点を確認
- 順位に使われるのは、締切時点で掲載した1件である

## 4. 第1回までに用意するもの

- 本戦入力の台帳：B・A_bg・全C・全課題・mia_columns・キット版のハッシュ、自チームID 28、対象集合
- 対象数は配布物から読み、予備戦の20対象や例示の29対象を固定しない
- 対象ごとの診断表：丸め、重複、背景との一致率、近傍距離、Cのtime分布、攻撃間の予測差
- 加工方式の断定ではなく、次に試す仮説を選ぶ材料とする
- 同条件の比較表：既存の4系統MIA・12系統AIAを共通の保存済みCで比較
- 似た出力しか出ない候補は、別の原理の候補に入れ替える
- 提出記録の様式：回・提出ID・日時・変更点・比較元・コードと入力のハッシュ・結果原本・次に採る判断
- 第4〜7回はMIAとAIAそれぞれの仮説を書く
- 環境はルート `.venv/bin/python` とHomebrew Python 3.12
- 依存はルート `requirements.txt` を使う
- 旧スターターキットの `.venv`、Conda、VPCKV環境は使わない
- 旧コードは固定Pythonパスとハッシュを確認し、新規実行器の子プロセスは `sys.executable` にする
- 過去の記録を上書きしない

## 5. 各回の採用・実行条件

| 確認項目 | 判断のしかた |
|---|---|
| ローカル性能 | 同じC・候補・パネルで元方式と比較／平均差、悪化した対象・条件、上位候補の変化を記録する／新手法が全条件で勝つことまでは要求しない |
| 情報の価値 | 次に採用／中止を判断できる仮説があること／微小な数値差、確定非会員の修正、過去最高の貼り合わせだけでは枠を使わない |
| 正解の分離 | 推定には許可されたB・背景・C・公開課題だけを渡す／自チームの真の希少ラベルをMIAに使う場合は明記する／模擬MIA所属真値・AIAのtime真値・標的対照ラベルは評価側に置く |
| 全体と希少 | MIAは双方のTPR、AIAは双方の的中率と誤差補正後Rを確認／真の希少対照がなければ「希少未評価」とする |
| 公式結果の解釈 | MIAのAUCや4段階帯だけで採否を決めない／AIAのφ、全員10年、背景1NNの基準を混同しない |
| 提出形式 | ZIP直下にF_mia.csv・F_aia.csv・token.txtの3つ／MIAのID・列、AIAの全ID、欠損・重複・値域を公式検証器で確認 |
| 最終採用 | 8回のうち採点済み最高の提出を維持し、最後に掲載IDを確認／計画の掲載は実際の提出を意味しない |

- 同じ有限の母集団から作るパネルは開発用である
- 300組を再抽出しても300の独立したコホートを確認したことにはならない
- 本戦Cへの優劣は公式結果で更新

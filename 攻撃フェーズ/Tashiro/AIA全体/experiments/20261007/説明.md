# 本戦 AIA全体を上げる方法の比較

2026年10月7日。Team 28。

**主案は、部分属性での近さを背景データで評価し、同じ加工行への対応の競合を解いて、性別ごとに75%を選ぶ方法です。** 予備戦の公開正解では、原記録を強く保持する2対象を外した18対象で、最近傍型基準の平均Rが0.0326、新候補が0.1117でした。新候補を本戦のチーム9以外の21対象で比較することを提案します。本戦で0.1432に到達した結果ではありません。【予備戦公開正解による再採点・提案】

## 1 前提

### 本戦の現在地と目標

| 指標 | 第1回 | 第2回 |
| --- | ---: | ---: |
| リーダーボードのAIA全体 | 0.073983 | 0.074787 |
| 補正後のAIA力 | 0.046505 | 0.052396 |
| 標的の時間正解率の平均 | 0.563581 | 0.656442 |
| 対照の時間正解率の平均 | 0.547128 | 0.637200 |

標的の正解率は上がりましたが、対照の正解率もほぼ同じだけ上がっています。全員の時間をよく予測することだけでは、AIA全体は伸びません。【公式スコア】

2026年10月7日6時42分に確認したCodaBenchの公開結果では、gghatanoのAIA全体が0.1432、Rが0.1273、tsugiyが0.1090でした。公開されていた3件の比較で、非公開の提出結果や相手のアルゴリズムは含みません。攻撃者ごとの対象集合も同一とは限りません。[CodaBench本戦](https://www.codabench.org/competitions/17698/#/results-tab)

リーダーボードのAIA全体は、対象別の `R_all = clip((p_m - p_c) / (1 - p_c), 0, 1)` の平均です。総得点に入るAIA力は、対象別に `clip(max(R_all, R_rare) - phi_k, 0, 1)` を計算した後の平均です。`aia_per_target` はこの補正後の値です。平均のp_mとp_cを式へ入れた値、総得点からMIA全体を引いた値のどちらも、AIA力そのものにはなりません。【公式コード】[採点実装](https://github.com/pwscup/pwscup2026-kit/blob/main-attack-20260928/starter/src/pwscup2026/kit/codabench/scoring_io.py)

### チーム9と他21対象を分ける

両回で同じ課題と基準補正phiが使われたという前提では、チーム9の補正前Rを一意に絞れます。163人ずつの正解人数から取り得る8,155種類のRを、2回の補正後スコアの差と照合しました。【公式スコアと公式コードからの推定】

| 推定した量 | 第1回 | 第2回 |
| --- | ---: | ---: |
| チーム9の補正前R | 67/87 = 0.770115 | 69/88 = 0.784091 |
| チーム9の標的正解人数 | 143 | 144 |
| チーム9の対照正解人数 | 76 | 75 |
| 他21対象の標的正解人数合計 | 1,878 | 2,210 |
| 他21対象の対照正解人数合計 | 1,886 | 2,210 |
| 他21対象の平均R | 0.040834 | 0.041010 |

チーム9のphiは約0.037890です。第2回の正解人数差69人は、この対象だけで説明できます。他21対象の差は合計0ですが、相手別には正負の差があるため、0未満を切ったRの平均は0.0410になります。チーム9だけを完全にしても、全体の改善余地は約0.00981です。【同上】

チーム9を維持してAIA全体0.1432を目指すなら、他21対象の平均Rは **0.112681** 必要です。ここを次の改善対象にします。推定の条件と全候補照合は [採点の追加推定](採点の追加推定.md)、[対象9と他21対象の集計](集計/対象9の補正前Rと他21対象.csv) を参照してください。

### 比較に使ったデータ

本戦は自チーム28を含む23組、実攻撃対象は22組です。Cは各1,049行、AIA課題は各326行で、標的163人と対照163人を含みます。公開QIはage、sex、prefecture、SBP、TG、HDL、ALTです。課題とCの公開7属性の完全一致は全23組で0件でした。【配布データ】

予備戦の21組の公開正解を開発比較に使い、自己5を外した20対象と、原記録を強く保持すると推定した1・2も外した18対象を併記します。1・2は未加工ではありません。本戦の他チームの正解は使っていません。自チーム28は会員選別と標的側の時間正解率だけを診断し、対照の時間が不明なのでRを計算していません。

今回実際に読んだ予備戦背景、旧キット背景、本戦背景は、それぞれ5,143行の別データです。主比較は予備戦背景5,143行で、旧キットとの合算10,286行も感度確認に使いました。ルートREADMEの古い行数記載を今回入力の行数には使っていません。[実測行数とSHA256](集計/入力背景の実測.csv)

## 2 仮説

標的と対照は性別、地域、年齢帯、onsetなどを合わせて作られます。一般的な健康リスクや長期生存を予測すると、両側に当たりやすくなります。Cに残る個人の部分特徴や、標的集団の細かな分布との差を使う必要があります。【公式ルール・推論】[本戦ルール p9](https://github.com/pwscup/pwscup2026-kit/blob/main-attack-20260928/rulebook/PWS_Cup2026_ルールブック_main-process-20260912.pdf)

検証した中心仮説は、5数値属性すべてで照合するより、**同じC行の中で差が小さい2属性**を使う方が、属性ごとに異なる加工に耐えられるというものです。ただし、背景でも起きる偶然の近さを補正しないと、珍しい値や探索回数だけで高い信号になります。独立した背景参照を使う考え方は、[DOMIAS](https://proceedings.mlr.press/v206/breugel23a.html)の密度比較にもあります。今回の部分対応はDOMIASの実装そのものではありません。

さらに、複数の課題が同じ加工行へ集中する対応を避けると、標的と対照の選別が改善する可能性があります。一対一対応はこの競合を調整する仮定で、合成Cに真の個人対応があることを意味しません。

## 3 分析方法と結果

### 主候補の手順

1. TGとALTをlog1p変換し、5数値属性を背景のIQRで尺度調整する。
2. 性別が一致する課題とC行の組について、5属性の二乗差のうち小さい2つを平均する。2属性は同じ候補行から取る。
3. 同じ距離計算を背景にも適用する。背景でその距離以内に入る割合が小さい組を高く評価し、経験的CDFを補間して同点を減らす。
4. 12近傍と、その境界に並ぶ同点行を候補にする。僅かな5属性距離で同点を解き、加工行の使い回しを避けて総評価が高くなる対応を選ぶ。
5. 性別ごとに75%を選び、選んだ245人は9.5年、残りは0年と答える。0は数値の時間回答で、正式な棄権ではない。

これは比較分析としてメモリ内で評価した手順です。提出用FやZIPは作成していません。コードは [同点に依存しない対応.py](同点に依存しない対応.py) です。

### 同じ対象での比較

14対象の共通比較では、自チームの予備戦最終回答が0.087206、公開上位の攻撃者19が0.127395でした。主候補は自チームの過去回答を上回り、上位回答へ近づきます。相手の実装を再現できたという結果ではありません。S4型基準も本戦第1回の提出ファイルそのものではなく、予備戦入力での比較用再計算です。【予備戦公開正解による再採点】[同一対象比較](集計/有力候補の同一対象比較.csv)、[公開回答の公平比較](集計/予備戦公開上位回答_公平比較.csv)

18対象で、主候補はS4型より13対象で改善、5対象で悪化しました。平均差は+0.079176です。対象単位の探索的ブートストラップ区間は約+0.0355〜+0.1227ですが、設定選択や方法の設計を含む不確実性は補正していません。

ラベル学習を使わない526設定から、評価する相手の正解を外して設定を選ぶ比較では、平均Rは0.107491でした。主候補の年齢除外・選択人数・9.5/10年回答の20設定だけで同じ比較をすると、すべて75%・年齢あり・9.5年が選ばれ、平均0.111736でした。いずれも過去の公開正解を何度も使った開発比較で、方法の設計自体が独立した未知データで評価されたわけではありません。【同上】[相手を外した設定選択](集計/学習なし全候補_相手を外した設定選択.csv)

### 偶然差と参照依存の確認

標的を含まない背景から1,049行を取り、Cへ差し替える対照実験を行いました。標本用の2,571行と参照用の2,572行を分けた30反復では、主候補の修正前の同等構成は、実Cで0.079595、背景Cで平均0.037079でした。差は約+0.0425です。この実験は公式phiの再現ではありません。公式の参照攻撃、反復数、入力条件と違います。【公開正解を使った背景差し替え実験】[平均](集計/対応競合頑健性_平均.csv)

参照を旧キット背景へ変えると、主候補と同等の連続スコア・性別内75%選別は0.067164へ下がり、予備戦と旧キットを合算すると0.107267でした。参照を増やせば必ず良くなるわけではありません。主案では各フェーズ自身の背景を使い、別背景の値を見て本戦の最良設定を決めません。【感度確認】[背景参照感度](集計/背景参照感度_加工群平均.csv)

同点処理後の主候補は、予備戦21組と本戦23組の全44Cで、課題・Cの行順を10通り変更しても選別が変わりませんでした。年齢を除くと18対象の平均Rは0.070226へ下がり、90%選別も0.073014でした。75%選別の改善は、単に回答人数を増やした効果ではありません。【再計算】[行順変更](集計/同点修正_行順変更平均.csv)、[属性と選択人数](集計/属性と選択人数_加工群平均.csv)

自チーム28では主候補が会員130人、対照115人を選び、標的の時間は107/163人に当たりました。これは選別の診断で、対照の時間がないため本戦のRやphi補正後の得点へは換算できません。【自チーム診断】[結果](集計/同点修正_本戦自チーム.csv)

## 4 結論と次の比較

**第3回のAIAで、チーム9を現行の比較基準として維持し、他21対象を主候補へ変更する案を推奨します。** 主目的は、他21対象の標的と対照の正解人数差を作れるかを調べることです。現在の他21対象平均Rは0.041010で、目標に必要なのは0.112681です。【提案】

| 今回変える点 | 比較するもの | 結果から判断すること |
| --- | --- | --- |
| 9以外の21対象を部分対応・性別内75%選別へ変更 | 第2回のAIA全体、AIA力、p_m/p_c、対象別補正後値 | 時間の正解率が両側へ上がる状態から、標的側へ差を作れるか |
| 9は第2回のN9を維持 | 9の補正後値0.746201が維持されるか | 既知の強い経路を比較基準にし、他対象の変化を読む |
| MIAは既存の第3回候補人数検証を併走 | MIA全体・希少と既存計画の人数条件 | AIAを固定したMIAだけの提出にしない |

複数の対象で補正後値が0から正へ変わり、AIA全体とAIA力の両方が伸びれば、新経路を次の検証へ残します。AIA全体だけが上がりAIA力が伸びなければ、偶然差や参照依存を再点検します。最良回答の対象別統合は、既存の第8回方針に残します。[本戦の第3回から第8回の進め方](../../../notes/第3回から第8回の進め方.md)

参考として、他21対象が予備戦18対象の平均0.111736と同じRを出すなら、チーム9を維持した全体は0.142298になります。これは移行が完全に成立すると仮定した算術で、本戦の予測点ではありません。実際の採用判断は、主案を作成・提出した後の公式結果で行います。

公式の本戦攻撃締切は10月11日21時です。提出の時刻は、10月10日・11日のCodaBench停止予定も含めて[公式案内](https://www.iwsec.org/pws/2026/cup26.html)で確認します。今回の作業は分析と提案までで、提出用CSV・ZIPの作成と実際の提出は採用指示後の別作業です。

# 予備戦MIA全体：全対象の排他性・人数制約を使う共同推定

**実験日：2026-10-09 JST／状態：実行済みの比較研究。今回の構成はP01の置換案として見送り。**

[全結果CSV](results/by_target.csv)／[集約CSV](results/summary.csv)／[プログラム](run_experiment.py)／[検証コード](test_experiment.py)／[MIA全体の入口](../../README.md)

## 1. 結論

**「ある相手に共有された人は別の相手には共有されない」という制約は、今回確認できる予備戦正解の範囲で成立した。しかし、その制約を既存スコアに追加しても、安定したMIA全体の改善は得られなかった。**

全背景・全20対象で、既存P01の平均TPR@FPR=0.01は **0.080798**。最大競合補正を追加した案は **0.080875** だが、差は **+0.000077** にすぎない。Team1で1人分改善する一方、Team10で1人分悪化した結果であり、背景の80%抽出を3通り試すと優位は消えた。ソフト割当・ハード割当はP01を下回った。[集計原本](results/summary.csv)

したがって、**現行P01をこの結果だけで置き換えない**。これは「排他性が役立たない」「共同推定のすべてが不可能」という結論ではない。今回の順位スコア、固定係数、全対象一律の割当についての結果である。本戦の提出物、MIA希少の固定5bit方式、AIAには変更を加えていない。CodaBenchには提出していない。

## 3. 比較した方法

### 3.1 基準スコアとP01

Gen-LRA7の実装と県×性別・縮約500の非会員較正は、[10/7の分析.py](../20261007/分析.py)と[非会員を使う順位較正の検討.py](../20261007/非会員を使う順位較正の検討.py)を変更せず呼び出した。2ファイルのSHA256を固定し、変更されていれば実行を停止する。

数値属性はage・SBP・TG・HDL・ALT、カテゴリ属性はsex・prefecture。TGとALTにlog1p、近傍10、rho=0.98を使う。対象自身を除く公開AIA課題を非会員較正標本とする。通常875人内の対象別平均順位を875で割ったものを `r[i,j]` とする。これは会員確率ではない。

```text
GenLRA7  = 較正前の生スコア順位
Q500     = r[i,j]
P01      = r[i,j] - 0.1 × median(r[i,k], k≠j)
```

今回再計算したP01とGen-LRA7は、[保存済み対象別結果](../20261007/非会員較正結果/非会員較正_対象別比較.csv)の全20対象について、それぞれ最大誤差1e-12以内で一致した。比較基準を別実装に差し替えた実験ではない。[回帰検証結果](results/run_record.json)

### 3.2 最大競合補正

他対象の「中央値」ではなく「最大」を使い、特定の相手との競合を強く下げる。

```text
max_λ                = r[i,j] - λ × max(r[i,k], k≠j)
P01_plus_max_0.1      = P01[i,j] - 0.1 × max(r[i,k], k≠j)
λ                    = 0.1, 0.25, 0.5
```

`max_λ` はP01の中央値補正を置き換える比較、`P01_plus_max_0.1` はP01への追加比較である。この2つを区別する。

### 3.3 人数条件：500〜511人と「観測対象外」

対象数をK、元のコホート数を30、全29相手との共有合計を736とすると、観測対象への共有合計の下限L・上限Uは次のようになる。

```text
L = max(25K, 736 - 27(29-K))
U = min(27K, 736 - 25(29-K))
```

予備戦K=20では `L=500, U=511`。本戦22対象の550〜561を転用していない。各対象25〜27人、全対象合計500〜511人、各人の所属先は1つ、という制約を同時に置く。

未知886人のうち、観測対象外へ割り当てる人数は `886-U〜886-L`、すなわち375〜386人である。「観測対象外」は自チーム非共有の未判明部分と、加工データのないコホートとの共有をまとめた受け皿であり、全員を20対象のどれかに押し込まない。

**通常875人だけに各対象25〜27人を割り当てると、希少共有者を二重に数えかねない。** そのため内部の割当には未知の希少11人も含める。ただし希少の提出用スコアは後述の共通値から変更しない。希少11人の入力順位は、通常875人の較正スコア列への挿入順位で拡張する。通常の順位と元のrが一致することはassertで確認している。

### 3.4 ソフト割当

未知886人×（観測対象＋観測対象外）の重み行列Pを求める。各行の重み合計は1、各列の合計は上記人数の範囲内とする。観測対象のスコアSはQ500の順位を未知886人へ拡張した値、観測対象外のスコアは全員0.5に固定した。

```text
最大化する量 = Σ S[i,j] P[i,j] - τ Σ P[i,j] log P[i,j]
各行          Σ P[i,j] = 1
各観測対象列  25 ≤ Σ P[i,j] ≤ 27
観測対象外列  375 ≤ Σ P[i,外] ≤ 386    （20対象の場合）
```

温度τは `0.02, 0.05, 0.1` の3つを固定し、主比較は `0.05` とした。容量の上下限制約に対応する双対問題をL-BFGS-Bで解く。得られた通常行のPを対象別に順位化する。**Pは較正済み所属確率と保証されたものではない。** また、今回のソフト割当の入力はQ500であり、P01にソフト割当の結果を混ぜた構成ではない。

### 3.5 ハード割当と同点の診断

同じS・同じ容量条件で、エントロピー項なしの割当を線形計画として解く。今回返った解の整数性と実行可能性を確認する。

`hard_rerank` は、割り当てられた対象の行を優先し、その内部と外部を元のrで順位付けする。内部スコアは `割当0/1 + 0.001r`。`hard_binary_diagnostic` はこの内部タイブレークを除いた比較で、通常行が2つの同点群に分かれる影響を見る。後者も最終値域変換を通すため、CSV上で単純に全候補を0/1にする方式ではない。

### 3.6 最終スコアと採点

全方式で、既知非共有163人は0、未知希少11人は0.4、通常875人は順位から0.6超〜0.9へ変換する。**比較対象間で変わるのは通常875人の順位だけ**である。これは今回の予備戦比較に共通する固定出力であり、本戦の固定5bit質問CSVを再現したものではない。

採点は1,049人全員のTPR@FPR=0.01。ROC上の線形補間を使い、人数の切上げや「上位10人固定」で代用しない。同点は群として処理し、record_idで人工的に分割しない。FPR=0.005/0.02、AUC、上位10/12/25の的中人数も保存する。上位人数の境界が同点なら、その群を無作為に並べた場合の期待的中人数を報告する。

## 4. 全背景・全20対象での結果

数値は対象ごとのTPR@FPR=0.01の単純平均。改善・同点・悪化は同じ対象のP01との差で判定した。**匿名性の偶然補正後の点、総合得点、攻撃力とは別の値**である。

| 方式 | 平均TPR | P01との差 | 改善／同点／悪化 |
|---|---:|---:|---:|
| Gen-LRA7 | 0.063177 | -0.017621 | 0／14／6 |
| Q500 | 0.065100 | -0.015698 | 0／14／6 |
| **P01** | **0.080798** | — | — |
| 最大競合0.1 | 0.069023 | -0.011775 | 0／16／4 |
| 最大競合0.25 | 0.063248 | -0.017550 | 1／14／5 |
| 最大競合0.5 | 0.037734 | -0.043064 | 1／13／6 |
| P01＋最大競合0.1 | 0.080875 | +0.000077 | 1／18／1 |
| ソフトτ=0.02 | 0.051325 | -0.029473 | 0／14／6 |
| **ソフトτ=0.05（主比較）** | **0.041325** | **-0.039473** | **0／13／7** |
| ソフトτ=0.1 | 0.051248 | -0.029550 | 1／12／7 |
| ハード＋内部順位 | 0.061100 | -0.019698 | 0／16／4 |
| ハード同点診断 | 0.050158 | -0.030640 | 3／7／10 |

主比較のソフトτ=0.05は、20対象で改善0・悪化7。最大の悪化はTeam2の **0.520000→0.160000** だった。これを上回る別の温度を結果から選んでも、試した3温度すべてP01未満である。[対象別原本](results/by_target.csv)

### 4.1 P01＋最大競合の僅かな差はどこから来たか

| 対象 | P01 | P01＋最大競合0.1 | 差 |
|---|---:|---:|---:|
| Team1 | 0.560000 | 0.600000 | +1/25 = +0.040000 |
| Team10 | 0.115385 | 0.076923 | -1/26 = -0.038462 |
| その他18対象 | — | — | 全対象で同じ |

20対象平均の差は `(1/25 - 1/26)/20 = 1/13000 ≈ 0.000076923`。広い対象群に効いた改善ではなく、分母が違う2対象の1人分の改善と悪化がほぼ相殺した結果である。単一平均の小数だけで採用しない。

今回の全1,380対象×方式評価で、帯2以上に達した対象はTeam1・2だけだった。**Team12以外で新たに帯2以上となる対象は得られていない。** これは過去の全方式を再評価した主張ではなく、今回保存した12方式条件の範囲である。

## 5. 背景と対象集合を変えても改善するか

### 5.1 背景Aの80%抽出

全5,143行に加え、4,114行を固定seedで3回抽出した。Gen-LRAの参照密度とスケールから毎回再計算しており、元の順位に乱数を足したものではない。

| 方式 | 全A | seed20261009 | seed20261010 | seed20261011 |
|---|---:|---:|---:|---:|
| P01 | 0.080798 | 0.078952 | 0.077023 | 0.076875 |
| P01＋最大競合0.1 | 0.080875 | 0.077028 | 0.077023 | 0.076875 |
| 最大競合0.1 | 0.069023 | 0.067177 | 0.069177 | 0.069100 |
| ソフトτ=0.02 | 0.051325 | 0.039402 | 0.047473 | 0.047325 |
| ソフトτ=0.05 | 0.041325 | 0.045402 | 0.047396 | 0.053177 |
| ソフトτ=0.1 | 0.051248 | 0.047402 | 0.053248 | 0.047100 |
| ハード＋内部順位 | 0.061100 | 0.053254 | 0.059254 | 0.051177 |

P01＋最大競合は抽出3条件で1敗・2引分け。ソフト3温度とハード＋内部順位は4背景すべてでP01を下回った。**同じAからの再抽出なので、独立した4データセットの検証ではない。** [全12方式の背景別値](results/summary.csv)

### 5.2 「評価から除外」と「推定から除外」を区別

まず20対象で共同推定した結果を固定し、平均を取る対象だけを変えた。

| 方式 | 全20対象 | Team1・2を除く18対象 | Team1・2・12を除く17対象 |
|---|---:|---:|---:|
| P01 | 0.080798 | 0.029775 | 0.027002 |
| P01＋最大競合0.1 | 0.080875 | 0.027638 | 0.024739 |
| 最大競合0.1 | 0.069023 | 0.023359 | 0.020208 |
| ソフトτ=0.05 | 0.041325 | 0.017028 | 0.013504 |
| ハード＋内部順位 | 0.061100 | 0.021222 | 0.017945 |

過去の18対象P01=0.029775と一致するのはこちらの条件である。

別に、**共同推定の競合先からTeam1・2、またはTeam1・2・12を最初から除く実験**も行った。この場合は対象数Kと人数条件も再計算する。例えば18対象推定ではP01=0.025495、ソフトτ=0.05=0.019250。17対象推定ではP01=0.024649、同ソフト=0.015857だった。

除外対象の公開AIA課題まで較正標本から消した実験ではない。生スコア・Q較正は共通とし、競合補正・割当問題への参加だけを変えている。17対象推定のP01＋最大競合は0.027002と基準を上回るが、別の対象集合・別の推定問題に変更した感度結果であり、全20対象への一般的改善とは扱わない。

CSVの `inference` と `evaluation` は別列である。異なる推定集合の値を、同じP01からの改善として混ぜない。対象集合の除外は背景fullのみで実施し、3つの80%背景では全20対象推定のみを行った。

## 6. 何が分かり、何がまだ分からないか

**確認できたこと。** 公開予備戦の範囲で排他性と人数条件に違反はない。今回の割当を数値的に解くことはでき、少なくとも今回固定した方法群はP01の安定した改善にならなかった。既存の中央値補正を最大競合に置き換えると、むしろ悪化する例が多かった。

**解釈上の仮説。** 排他性は「矛盾する所属を許さない」情報であって、「どちらが正解か」を直接教える情報ではない。誤った高スコアを強く競合させると、別チームの正解候補まで押し下げる可能性がある。また、全886人を容量に合わせる目的と、各列のごく上位を重視するTPR@FPR=1%は同じ目的ではない。これらは悪化の説明候補であり、本実験だけで原因を分離した証明ではない。

**未実施・限界。** 他の基礎攻撃スコア、P01を入力にしたソフト割当、P01との混合、対象別の信頼度を使う重み付け、高信頼の所属だけによる排除は試していない。dummy=0.5を含む全係数の最適性も主張しない。既に繰り返し探索された予備戦の同じ候補集団を用いており、今回の実行内で予測を先に固定しても、未接触の独立評価にはならない。本戦で良くなるかは不明である。

## 7. 検証と再現

[検証コード](test_experiment.py)には10テストがある。小規模ハード割当と全探索の一致、ソフト双対解と別実装の主問題SLSQP解の一致、ソフト解の行・列並替えへの整合、無情報スコアから行ごとの区別を捏造しないこと、人数上下限、競合先から自列を除くこと、通常順位の拡張、固定行の維持、同点ROC・完全順位・帯境界を確認する。

さらに全実験で実行可能性・双対ギャップ・相補性、ハード解の整数性、独立に集約したROCとscikit-learnの一致を検査する。これは有限入力の数値検査であり、任意入力への形式証明ではない。[検証出力](results/tests.txt)／[最適化診断](results/optimizer_diagnostics.json)

今回の構成は12方式条件×6入力・推定条件＝72予測行列。対象数20/18/17の違いにより、対象×方式の結果は1,380行。4種類の評価集合への集計は288行であり、重複する集合も含む。72個の独立手法や独立データセットを作ったという意味ではない。

リポジトリルートで、次を実行する。既存結果は上書きせず、新しい出力先を指定する。

```bash

python3.13 -m venv .venv-mia-joint
.venv-mia-joint/bin/python -m pip install -r "$EXP/requirements.txt"
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  .venv-mia-joint/bin/python -m unittest discover -s "$EXP" -p test_experiment.py -v
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  .venv-mia-joint/bin/python "$EXP/run_experiment.py" \
  --root . --output-dir /tmp/mia-joint-prelim-new-run
```

参照環境はPython3.13.5、NumPy2.3.5、pandas2.2.3、SciPy1.17.0、scikit-learn1.8.0。`--full-only` は全Aのみの短縮検査用であり、保存した全実験を再現するときは付けない。assertによる検査を無効化する `python -O` は使わない。公開済み予備戦正解があるこのリポジトリ配置に対応しており、本戦用の汎用提出生成器ではない。

# P08-D：上位候補だけの疎な排他補正を検証

**2026-10-09／予備戦研究。新方式の本戦採用・公式提出は未実施。**

## 動機・背景

[P08の全研究案](../../proposal/P08_別視点の改善仮説と検証優先順位.md)のDを実験する。これまでの[P02共同推定](../20261009_P02_AIA二対象外共同推定/README.md)では、通常875人・希少11人を含む886候補に全対象の容量制約25〜27人を課し、ソフト/ハード割当の多数の設定を試してもP01を安定して上回らなかった。今回の**局所版**は、候補者が複数標的の上位に入る場合にだけ弱い抑制を行う。全候補の所属を必ず決めることはしない。

公式予備戦で公開済みの22コホート分 `pool_ids` の事後監査では、自チーム候補者が複数の相手に同時所属する事例は0。**この排他性だけで正しい所属先を特定できるわけではなく、スコアが高い方が必ず正しいとは限らない。** 真値は予測・診断・係数を凍結してからのみ読み、競合先を決める入力には使用しない。

## 計算上のキーアイデア

- P01：自チーム通常875人の各標的に対するGen-LRA7＋他Q較正＋他チーム中央値0.1補正の元スコア。
- 各標的のスコア上位**10/20/40人**に入る候補だけを見る。同点境界は `rankdata(-score, method="min")` によってひとまとめに残し、記録IDによる不自然な解決を避ける。
- 候補者iが**2標的以上の上位**に現れた場合だけ競合と定義。本人についてもっとも高いP01スコアの対象を「暫定リーダー」とし、他の競合対象でリーダーとの差が **0.02/0.05/0.10以上** の場合だけ、負け側のP01スコアから**0.05/0.15** を引く。順位交換は、その後の通常スコア順位変換で発生し得る。
- 全18条件＋元P01=19方法を事前に固定。**競合していない候補と暫定リーダーのスコアは不変**。候補者を誰かのBへ強制所属させない。
- 公開仕様に基づく少数の条件であり、個々の対象番号、公開予備戦の正解TPR、勝敗ラベルに応じて切替しない。ただし今回の仮説自体は正解公開後の研究である。

## 比較・採否基準

1. 最初に**正解を読まず**、上位kに現れた候補の実人数、複数対象で競合する候補の人数、競合のために変更される個人×標的セル数、スコア差の分布を保存。競合がごく少ない場合は、性能改善の余地が小さいという否定結果もそのまま報告。
2. 予備戦20対象（推定・評価とも20）と、Team1・2を推定・評価から除く18対象を**別々に**全4背景（full・同じ予備戦A_bgの80%を固定seedで3回）で再計算。
3. 指標は公式ROC同点処理・線形補間に従うTPR@FPR=0.005/0.01/0.02、TPR0.10以上の新規達成/喪失、既存P01のTeam10/24等の改善・悪化、帯2以上の対象数。
4. 旧予備戦実提出のMIA希少・AIAとTeam1・2の高得点を維持する**仮想得点**は参考に掲載。ただしこれは**全対象P01との比較**であり、P04のKDE A/B成果を取り込んだ統合得点ではない。P04の0.349197とは評価方式が異なるため単純に加算しない。
5. 全ての個人予測をSHA256で凍結後にだけ公開予備戦正解で評価。公開A_bgの複数抽出は同じ予備戦データ由来で、独立汎化性能の測定ではない。方式条件18個を探索した事後最高をそのまま本戦採用方式と呼ばない。
6. 本戦の相手B・本戦真値は取得せず、提出CSV、P01、希少MIA固定5bit、AIAの現行方式を変更しない。

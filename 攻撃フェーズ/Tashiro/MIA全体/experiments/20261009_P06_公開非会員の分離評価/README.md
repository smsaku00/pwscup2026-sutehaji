# P06：公開Aの非会員保留でP01・KDE A・P03の誤検出を比べる

**2026-10-09／公式予備戦の探索的比較。P06は元P04からのTPR・仮想攻撃力改善なし。本戦提出・方式採用は変更しない。**

## 研究目的

[P05](../20261009_P05_損失防止と公開特徴ゲート/README.md)は、予備戦の公開正解を見た後にTeam7・18の失点に合わせて切替条件を定義したため、仮想攻撃力0.355120を出しても17対象保留で改善が消えてしまった。次は**公開の既知非会員を評価専用に取り置く**ことで、所属正解を知らずに、どの方式が誤検出を増やしそうか判断できるか試す。

## 方法

- 公式予備戦の公開背景A_bg（5,143行）を3つの固定乱数で**80%参照／20%=1,028行を完全保留**する。保留Aは密度推定やGen-LRAの背景参照に入れず、誤検出リスクの評価専用とする。3つの保留は同じAからの再抽出なので独立試験と呼ばない。
- 予備戦自チームB_selfは1,049行、通常の順位付け対象875行。各方式について875候補の上位1%／5%に相当するスコア閾値を設け、保留Aのうち閾値を上回る割合（**proxy false-alarm rate**）を記録する。**公式FPRではない**。背景Aと自チームBでは分布が異なり、真のMIA非会員1024人の直接的な標本ではない。
- 比較する個人スコア：**P01**（Gen-LRA7＋他コホート公開AIAによる県性別層経験CDF較正500＋他チーム中央値補正0.1）、**KDE A**（元13属性・中央値IQR整列・h0×2・カテゴリ一致平滑化・他チーム中央値補正0.1）、**P03**（P01＋C最近傍の順位に0.1を加算）。いずれも20対象共同推定の同じ背景上で計算する。
- P01の較正に使う公開AIAチャレンジは評価専用A_bgと別。補助監査として、B_selfと自チーム公開AIAが一致する**163人（通常150人＋希少13人）の既知非会員**の順位も調べるが、**その163人の元データはP01の較正用Qにも含まれる**のでインサンプル。方式選択には使用しない。
- **対象の割当を変更できるのはP04でKDE Aだった5対象（予備戦Team3・7・8・13・23）のみ**。KDE Bは元の個人別順位を完全に再現できる原コードがリポジトリに揃っていないためリスク評価対象から外し、公式予備戦の保存TPRをそのまま使う。他対象のP01も変更しない。
- KDE AをP01またはP03へ切り替える判定規則は、保留Aでの上位1%誤検出割合を0.005以上減らす案／上位5%誤検出割合を0.010以上減らす案／1%誤検出を3分割全部で減らす案。**判定は、公式予備戦のpool_idsによる所属正解を読み込む前に確定する**。
- 予備戦の公式攻撃力は旧提出のAIAと希少MIA・Team1/2のTPRを固定し、Team12にP01を代入して計算した**仮想合成値**。実提出・公式採点の再現ではなく、元の公式旧攻撃力0.329795を再現することを検査する。

## 評価の制約

1. 保留Aのproxy誤検出は、真のFPR@0.01と同じ統計量ではない。1,028件中の数件差は統計的不確実性も大きく、複数分割での符号・対象保留での転移を重視する。
2. P04の公開特徴群と今回の切替候補は、過去に公式予備戦の公開正解を繰り返し見た研究過程から来ている。**今回の予測確定→真値監査の順序だけで独立検証済みとは言えない**。
3. KDE Bの個人別riskを測定していないため、「P01/KDE A/KDE B/P03の全方式がリスク比較可能」という主張はしない。
4. 本戦B_self、非公開相手B、本戦所属真値、提出CSV、固定5bit符号は読み書きせず、**本戦のTPRを推測しない**。
5. 全スコアベクトルは計測中メモリのみ。GitHubへ保存するのはチーム別の誤検出人数・TPRと予測ハッシュのみ。

### なぜ誤検出率を最小化するだけでは危険なのか

結果を見て閾値を緩めるのではなく、公開Aの上位1%／5%誤検出率が**小さい方を無条件に選ぶ負の対照**を追加した。

[負の対照の再現コード](audit_aggressive_null_selector.py)／[4ルールの総合点](aggressive_null_audit/unconstrained_null_selection.csv)／[5対象の選択内訳](aggressive_null_audit/unconstrained_null_targets.csv)／[CI成功](https://github.com/smsaku00/pwscup2026-sutehaji/actions/runs/37931550630)。

| 公開A_BGの誤検出率で選ぶ方法 | 仮想攻撃力 | TPR0.10以上/20 |
|---|---:|---:|
| P04のKDE Aを維持 | **0.349197** | **6** |
| 公開Aの1%誤検出率最小化（P01対KDE A） | **0.341197** | **5** |
| 公開Aの5%誤検出率最小化 | **0.341197** | **5** |
| P01の1%誤検出が0.002以上小さければ切替 | **0.341197** | **5** |

Team13は公開A_BG保留3分割の平均上位1%誤検出率が **P01 0.006809、KDE A 0.009079** とP01に若干有利だった。しかし公式予備戦の真のMIA TPRは **P01=0、KDE A=0.16**。P01へ切り替えるだけで総攻撃力を **0.008** 失った。両方式の誤検出率の差は保留サンプル上で **延べ7行/3,084行**にすぎず、3つの保留集合も一部重複している。統計的に優劣が確定したとは呼べない。

Team7も同様で、公開A_bg保留の平均上位1%誤検出率は **P01 0.009403／KDE A 0.008755／P03 0.011673**。P03が真のMIA TPRを上げるという過去の予備戦結果があるにもかかわらず、公開A保留ではむしろ誤検出が多い。この誤検出指標だけでは「P03を選ぶべき対象」の識別につながらなかった。

### 公開非会員の「母集団」によっても判定が変わる

参考の自チームAIA由来の163人（通常150人＋希少13人）は、全対象Bに含まれないことを**正解を読む前の公開構造から**特定していた。ただしこの163人と重なる公開Q5はP01の較正用Qに含まれており、**P01では評価用の独立標本ではない**。

Team13では、その163人における上位1%超過は **P01が3/163、KDE Aは0/163**。対して背景Aを保留するとP01の方が僅かに低い誤検出率だった。**母集団・分布が異なり、しかも較正への混入がある指標を混ぜ、都合の良い方だけを信頼してはならない**。

ここでの公開A_BGのproxy false-alarmは、実際のB_self所属正解を使って算出する**公式FPR=0.01ではない**。候補B_self875行は真の会員も含むため、候補の上位1%で閾値を決める操作は、公式の真の非会員分布で1%を確保する操作とは異なる。

## 最終判断：P06は本戦方式の採用根拠にならない

- **保守的な公開非会員リスク選択3条件は全てP04を維持し、予備戦の仮想得点は0.349197から増えなかった**。誤検出率最小化を緩めた負の対照は0.341197へ悪化した。
- KDE Bの元の個人別スコアがソース不足でこのリポジトリから再現できなかったため、**KDE Bの誤検出を計測・比較したとは主張しない**。KDE B対象は過去の集計TPRを維持した。
- これまでのP04/P05の方式族・しきい値は、すでに予備戦正解を見て選んでいる。P06の選択を真値読み込み前に確定しても、**研究全体の事後選択バイアスは解消しない**。
- 原理的には、公開A_bg（どのBにも含まれない）の誤検出だけでなく、**実際の攻撃候補と同じ分布に属する非会員の較正誤差**を監査する必要がある。しかし公開AIAの既知非会員163人は既存P01の較正に使用済みなので、完全独立な評価標本を別途定義しなければ信頼できない。
- **本戦P01、提出CSV、希少MIA固定5bit、AIAには変更を加えない。**

### 次に実験するなら

- P01較正用Qを訓練・検証で**コホート単位に完全分離**し、対象外Qから採点用の非会員を確保する。背景Aを保留するだけでなく、攻撃候補B_selfの分布差を減らす。
- 元KDE Bの式と依存ソースを揃えてP01・KDE A・KDE B・P03の**同一背景・同一推定対象20チーム**で数値再現を通す。
- **FPRだけを最小化せず**、公開非会員のスコア較正が真の対象保留TPR@1%の改善を説明できるかを、別の予備戦または独立検証で確認する。

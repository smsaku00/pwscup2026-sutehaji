# P07：公開AIAコホート単位の保留によるP01・P03較正リスクの検証

**2026-10-09／公式予備戦の再計算・監査が完了。P01→P03のQコホート保留による改善は見つからず、本戦方式は変更しない。**

## 背景・目的

[P06](../20261009_P06_公開非会員の分離評価/README.md)では、公開背景A_bgから20%（1,028行）を独立参照に保留し、元P01・KDE A・P03の誤検出指標を測った。保守的な選択はP04を維持し、単純な誤検出率最小化では予備戦Team13の有望なKDE AのTPR0.16を失った。**A_bgと実際のB_self候補で分布が異なる**ため、次は公開AIA課題Qの同一較正集合への混入を避けた評価を行う。

## 重要な仕様上の制約

公開AIA課題 `aia_challenge_<k>.csv` は `age,SBP,TG,HDL,ALT,sex,prefecture` の**公開7属性**と`challenge_row_id`を含む。**元KDE AはBMI/FPG/time等を含む13属性を使うため、公開QからKDE Aの元の13属性スコアは直接計算できない**。不足値を勝手に補完して元KDE Aの誤検出と呼ぶことはしない。元KDE Bの個人別スコア再現に必要な元ソースも現リポジトリに欠けているため、KDE A/Bへの切替は行わず、**P04でP01に割り当てられた対象だけP01とP03を評価**する。

P01/P03は公開QI7のうち数値5属性（年齢・SBP・TG・HDL・ALT）と性別・県に基づくため、公開Qの各326行に対して同じ定義のスコアを求められる。

## 方法と監査境界

1. 公開予備戦のQコホートを**ファイル単位**で保持し、自チームQ5は必ず保留、追加5コホートは対象の真値を参照せず固定乱数 `20261009` で選択する。
2. 標的tを判定するとき、保留コホートh（tと異なる）のQ_h **326行**を非会員代理評価とし、P01の較正集合から**Q_hファイル全体を除外**する。他Qファイルに同じ7属性レコードが重複していれば、その一致行も較正集合から除外する。どのデータを取り除いたか件数を保存する。
3. P01：`GenLRA7`の生スコアを背景A/Cから一度計算し、保留h以外のコホートQで県＋性別層の経験CDF（縮約500）を構築。P03はこのP01に公開Cの臨床最近傍順位×0.1を加える。両者の標的スコアは**同じ予備戦20対象の他チーム中央値補正**を使う。
4. B_selfの通常875人の候補スコア上位1%／5%閾値に対する保留Q_hの超過割合を、各方式の非会員`proxy false alarm`として保存する。**これは真のFPR@0.01そのものではない**。対象t自身のQ_tはその標的の非会員ではないので必ず評価から除く。
5. P04でP01だった対象にだけ、上位1%の超過を0.005以上低下、上位5%を0.010以上低下、全保留コホートで上位1%超過を減らす、無条件で1%超過を最小化、という比較規則を適用する。原P04のKDE A/B割当は固定。
6. **全ての個人スコア・方式選択を凍結してから**、公式予備戦の公開正解 `pool_ids` を読み込んで20対象TPR@FPR=0.01を計算。元P01・KDE Aのfull結果を過去保存表と数値回帰。公式旧MIA希少、AIA、予備戦Team1・2の旧高得点、Team12のP01予測を合成する仮想攻撃力だけを比較する。

**留保：** Q_h課題は対象hの公開AIA課題であり、標的tとは異なるコホートの非共有抽出を根拠に非会員代理とする。Q同士の人物重複を7属性一致で除去したとしても、**Qの標本分布が実際のB_self非会員分布と同じとは限らない**。また群分け・係数を含む方式設計は既に同じ予備戦正解を見た事後探索履歴を持つため、真値を最後に読むだけで独立検証済みとは主張しない。

### Qコホートの評価用分割

公開AIAコホートは **Team5・7・9・10・13・26の6つ**。Team5は自チームのQ、残り5つは公開情報だけから固定乱数seed=20261009で選んだ。各Qコホートは326行。**評価標的とQコホートが同じ場合は非会員評価から除外**した。

Q_hの7属性一致レコードを、残りの較正用Qからも取り除く検査を実装。**今回の全対象・全保留組合せで他のQコホートに完全一致する7属性行は0**で、コホート単位の分離を確認できた。これは7属性の一致に基づくもので、公開されていない別属性での人物同一性を証明するものではない。

### 解釈：非会員判定の代理指標の限界

- P06の背景A分離でも、P07の同じQI7でのQコホート保留でも、**低誤検出率の方式が高TPRの方式とは限らない**。
- 背景AはB_selfと分布が異なり、Q_hはB_selfに近い公開臨床7属性を共有する一方、KDE AのBMI/FPG/timeなどの欠損6属性を持たない。よってKDE Aの真のスコアをQ_hで直接評価できず、P05で問題となった「KDE A↔P03切替」を直接解決するものではなかった。
- 元KDE Bは過去の固定方式再計算コードに外部ソースへの参照があるが、当該原Pythonファイルは現デフォルトブランチにも該当パスのGitHubコミット履歴にもない。**元KDE Bの内部個人順位・公開非会員リスクを再現・比較したことにはならない**。
- **実装上は予測を確定後に公式予備戦の正解を読み込む**。しかし既存P04方式群・切替規則は以前に予備戦の真値を参照して発案されているため、この順序だけで独立な汎化評価ができたとは言えない。
- P07の希少・AIA成分は予備戦旧公式採点値を固定した**仮想反実仮想**。実際の本戦の順位・TPRや追加提出の得点ではない。

## 最終採否：P07は本戦への方式更新に使わない

**P07で新しいTPR0.10達成チームは0。P01/P04の性能を再現したが、Qコホート保留によるTPR/攻撃力改善は0。積極的なP03切替は悪化した。**

今後の研究として優先するのは、(a) 現在欠落しているKDE Bの原実装・評価順序を復元し元の個人スコアと厳密な数値検算を行うこと、(b) 予備戦とは別の検証データと公開手掛かりを用意して方式選択の一般化を判定すること、(c) 真のFPR=1%とproxy false-alarmの関係を分析し、B_selfと公開Q/Aの母集団差を定量化すること。

現時点では**「誤検出率が低そうな方式を採用する」一般ルールは支持されない**。本戦の回答、MIA希少固定5bit、AIAの方式、実使用P01は変更していない。

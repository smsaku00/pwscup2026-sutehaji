# 予備戦Cを本戦ルールで評価するとどうなるか・同じチームの加工変更

確認日: 2026-10-10。予備戦で提出されたCを固定した採点式の比較と、実際の予備戦C・本戦Cの出力比較をまとめた。

## 結論

- **自チーム「ステテコは恥だが役に立つ」（予備戦5）のUは、0.982588から0.786179へ。** 元B・C・採点参照値・予備戦背景を固定したローカル再採点で、本戦に追加された相関得点がボトルネックになった。公式依存ライブラリ30件を固定し、旧ルールの4成分は公式値と最大4.13×10⁻¹¹の差で再現した。
- **他チーム20組の正確なUは計算できない。** 元Bと採点参照値が不足するため、Cから確定する新しい重複・打切り項目だけで成立する上限と、旧公式点も移せるという条件付きの範囲を分けた。「あれ」はU≤0.750000、「神ぼ大」はU≤0.860582、「Asakatsu2026」はU≤0.946378と旧Uより下がることが確定する。
- **Uの低下と総合点の低下は別。** 総合=min(U,Anon)。「あれ」は旧総合0.858909から上限0.750000への低下が確定するが、神ぼ大・Asakatsu2026はAIA背景補正でAnonが上がり得るため、総合低下までは確定しない。自チームの総合は0.538462〜0.786179の論理範囲になる。
- **同じチームでも、加工後の出力は多数で変化している。** 本戦23チーム中21組のCを対応比較し、強い変更兆候9、表現・後処理の変化4、中程度2、強い根拠なし6、比較不可2に整理した。相手の生成アルゴリズムの名前や変更確率を確定したものではない。

## この再評価で固定したもの

### 有用性U

各チームの予備戦のC、元B、元の採点参照値と予備戦A_bgを固定し、本戦加工版main-process-20260912のコード・設定へ変更する。実際の本戦では元B・C自体が変わるため、本表は実際の本戦リーダーボードでも将来得点の予測でもない。

- U=min(U_gen,U_spec,U_rare,U_valid)。U_genは従来の3項目に相関と裾の一致を追加したmin-5。
- 旧公式台帳を転用する狭い範囲は、既存の採点成分が予備戦default読込と本戦round_trip読込の有限精度差で変わらない条件付き。実行AST一致だけでは数値の完全一致までは保証できない。C単独上限はこの条件に依存せず、上記3チームのU低下と「あれ」の総合低下を支える。
- U_specとU_rareは実行ASTの一致を確認。U_validは打切り処理を変更し、重複・背景に対する新規性を追加した4項目平均。
- 公開Cだけで元Bを推定して得点を埋めていない。20チームのU下限0は「不足する入力について広く取った下限」であり、0点になるという予測ではない。上限の大小を順位として扱えない。
- 自チーム5だけは元Bと採点参照値があるため、上下限に局所的な再計算値を入れた。主因は相関得点0.786179で、裾0.989799、新規性1.0。相関の90パーセンタイル誤差0.171057を1−誤差/0.8で得点化した項目が最小になった。

### 匿名性Anonと総合点

予備戦の全攻撃提出、真値、希少フラグ、攻撃参加者を固定する。この条件ではMIA成分は同じ。本戦で追加されたAIA背景補正φは、予備戦の世界・コホートに対応する値が未取得である。

- AIA_main=clip(AIA_pre−φ,0,1)、Anon_main=1−max(MIA_pre,AIA_main)。
- 0≤φ≤1に対し、Anon_pre≤Anon_main≤1−MIA_pre。これは論理的な範囲で、信頼区間・予測区間ではない。実際の校正で端点が達成されることも主張しない。
- 9チームはMIAがAIA以上なのでAnonを一点に確定できる。12チームはφに依存する。未提出bot035は欠損。
- Ritz・HarunaDan@GUはMIA=1のため、Uやφが不明でも総合は0に確定する。この凍結条件での結論であり、実際の本戦成績を意味しない。
- 総合の範囲は[min(U下限,Anon下限), min(U上限,Anon上限)]。大会の予備戦0.1・本戦0.9の合算ではない。

## 加工方法の変更について

公式のphase別対応表でチーム名と選定提出IDを結合した。同じ番号を同じチームと扱わない。例えば自チームは予備戦5→本戦28、神神公社は7→5。

公開Cから確認できるのは、丸め・重複・値の種類数・背景との一致・分布・依存構造などの出力上の変化。元データ、乱数、パラメータ、実装、後処理の違いをすべて識別することはできない。自チームだけは元B対Cの比較で、age/sex/smokingの周辺分布保持が変わったことまで確認した。都道府県は両phaseとも元Bの度数を保持している。

## 検証と再現

- `build_score_summary.py`は同梱された集計CSVだけから得点一覧を再生成する。`python build_score_summary.py`で実行し、22行・欠損・総合の範囲・確定低下を検証する。
- 有用性の元C21件を公式台帳のSHA-256と照合。公開用CLIの境界計算と自チーム再採点を独立に再実行し、表と一致を確認した。詳細は[有用性](utility/README.md)。
- 匿名性では公式表の420件のMIA集計と21件の総合点を照合。公式の20,000回置換による偶然補正値は再利用し、置換を再実行してはいない。標的23・攻撃者4のAIA行列の空欄は維持した。
- 加工比較は44件の公開Cのハッシュを照合し、元の比較・丸め感度・自チームB対Cの集計を保存。再現入力は[説明](processing_changes/README_REPRODUCE.md)を参照。
- 掲載物は説明、チーム・指標単位の集計、再現コードと公開採点ソース。生のB/Q/C、個人別予測、非公開の採点参照値、依存ライブラリの実体は追加しない。

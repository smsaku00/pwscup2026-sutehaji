# 枝分かれ探索アルゴリズム調査（2026-10-07）

## 結論

現在のMIA希少6回完遂問題は、古典的なgroup testingだけでなく、より直接には

- **adaptive hypothesis identification**
- **optimal decision tree synthesis**
- **AND/OR search**

として定式化するのがよい。

現在の「軌道ごとに第4回を探し、第4回枝ごとに第5回を探し、第5回セルごとに第6回を検証する」実装は、最適決定木探索を手作業で展開しているのに近い。

今後は **AND/OR search + memoization + symmetry canonicalization + branch-and-bound** を中核にし、質問候補生成に minimax/Generalized Binary Search と limited-discrepancy/beam search を使う構成を推奨する。

## 1. 問題の形式化

現在の候補配置集合を version space `V` とする。

1回の質問 `q` は各真相 `x∈V` に6 Teamのcountベクトル

`h_q(x)=(h6,h10,h11,h16,h17,h25)`

を返し、`V` を結果別の部分集合 `V_{q,r}` に分割する。

残り質問数を `d` とすると、完全識別可能性は

`SOLVE(V,d) = exists q such that for every reachable result r, SOLVE(V_{q,r}, d-1)`

で表せる。

これは

- OR node: 「どの質問qを選ぶか」
- AND node: 「返り得る全結果枝が解けなければならない」

という **AND/OR tree** そのもの。

## 2. 文献で有力な方法

### AND/OR search + caching

Verhaeghe et al. のoptimal decision tree向けConstraint Programmingでは、AND/OR search、caching、branch-and-boundの組合せを主要構成としている。

https://www.ijcai.org/Proceedings/2020/662

今回にも最も近い。

### Caching branch-and-bound

DL8.5はoptimal decision tree探索で、部分問題cacheとbranch-and-boundを組み合わせ、従来MIPより大幅に高速化したと報告されている。

https://ojs.aaai.org/index.php/AAAI/article/view/5711

今回ならcache keyを「現在のversion space V + remaining depth d」とする。

### Generalized Binary Search

GBSは現在のversion spaceをなるべく均等に分割する質問をgreedyに選ぶ。

https://proceedings.mlr.press/v84/mussmann18a.html

今回のmulti-outcome版では、

- 最大bucket最小化
- entropy最大化
- sum of squared bucket sizes最小化

を質問順序付けheuristicとして使える。

ただしgreedy単独では「残り回数で必ず解ける」保証にならないため、AND/OR exact searchのquery orderingとして使う。

### Anytime beam / Limited Discrepancy Search

2025年のCA-DL8.5は、optimal decision tree向けにcaching branch-and-boundへbeam search / limited discrepancy searchを加えたcomplete anytime探索を提案している。

https://arxiv.org/abs/2508.06064

今回の「まず良い質問を早く見つけたいが、最終的には完全性も欲しい」という要件と合う。

### SAT / MaxSAT / Constraint Programming

固定深さtreeの存在判定はSAT/CPへ符号化できる。

- SAT optimal decision tree: https://www.ijcai.org/proceedings/2018/189
- MaxSAT: https://www.ijcai.org/proceedings/2020/163
- CP/AND-OR: https://www.ijcai.org/Proceedings/2020/662

ただし今回の質問は各nodeで6 Teamのsubset maskを選び、最大216 outcomeへ分岐するため、巨大なtree全体を一括SAT化するより、**lazy AND/OR searchで必要なnodeだけ生成**する方が自然と考える。

## 3. 今回向け推奨アルゴリズム

### 外側: exact AND/OR solver

`solve(V,d)` をmemoizeする。

1. `|V|=1` → success
2. `d=0` → fail
3. admissible lower boundで不可能ならfail
4. query候補を良い順に列挙
5. 各queryについて全結果枝を再帰
6. 全枝successのqueryがあればsuccess

### Cache

`cache[canonical(V), d]`

を使う。

すでに第3回209枝を53軌道まで圧縮できているので、同じsymmetry canonicalizationを再帰内部にも適用する。

### 質問候補生成

6 Teamのmask組 `1024^6` を直接探索しない。

1 Teamずつ部分質問を追加するbeam searchにする。

- depth0: empty partition
- depth1: Team6 mask 1024候補
- depth2: Team10を追加
- ...
- depth6: 完全な質問

partial partitionごとに

- 現在の最大bucket
- 残りTeamで理論上どこまで分割可能か
- depth-2 viability
- entropy / sumsq

で枝刈りする。

同じpartitionを作るmaskはdeduplicateする。

### 最終1回はset-coverとして厳密解

残り状態集合Sに対し、各Team maskは「どの状態pairを区別するか」というbitsetを持つ。

第6回の存在判定は

「6 Teamからmaskを1つずつ選び、全状態pairをcoverできるか」

というmulti-choice set coverとして扱える。

現在実装済みのpair-cover DFSをここに統合する。

### depth-2 lower bound

他5 Teamを固定したfiberごとに、ある2人Teamが残り2質問で識別可能かを事前計算する。

現在code30探索で使っている

- valid q5 masks per fiber
- intersection emptyなら即fail

は非常に強いadmissible pruningなので、そのままsolverへ入れる。

## 4. 推奨探索順

### Phase A: heuristic solutionを早く得る

- minimax split
- sumsq
- entropy

でqueryを順序付け。

beam幅を小さく開始し、LDSでgreedyから少数箇所だけ逸脱する。

### Phase B: 完全性を回収

解が見つからない場合、beam幅/discrepancyを段階的に増やす。

cache済み部分問題は再利用する。

最終的に候補queryを全探索すればcomplete。

## 5. 現行コードからの変更案

現在の

`orbit -> q4 random search -> branch screen -> q5 random search -> q6 exact`

を、

`solve(version_space, remaining_depth)`

の1本にまとめる。

具体的には:

- `VersionSpace`: state ID bitset / sorted ID array
- `canonicalize(V)`: Team/candidate symmetryで代表化
- `lower_bound(V,d)`
- `generate_queries(V,d)`: beam/LDS
- `partition(V,q)`
- `solve_last_query(V)`: pair-cover exact
- `memo[(canonical(V),d)]`

を実装する。

## 6. 優先度

1. **AND/OR + memoization**
2. **再帰内部のsymmetry canonicalization**
3. **query生成のbeam/LDS**
4. **depth-1 pair-cover / depth-2 fiber pruning**
5. 必要ならSAT/CP-SAT
6. 状態集合表現がボトルネックになった場合のみZDD/BDD

ZDDは巨大な集合族を圧縮できるが、現状2.5M states自体はmemoryに載るため、まずbitset/cacheの方が実装コストに対する効果が高い。

## 7. 現時点の判断

**現在の枝ごとの手作業探索をそのまま50軌道続けるより、ここでAND/OR solverへ切り替える価値が高い。**

最大軌道を3つ解いて得たq4/q5/q6 decision treeは、solverのheuristic初期解・cache seedとして再利用できる。

# MIA：第3回以降は何をするか

2026年10月7日に参照先を更新しました。以下は2026年10月6日当時の説明です。田代の主担当はMIA希少であり、全体MIAへの言及は補助的な比較案です。最新の短縮探索は [MIA希少の入口](../../README.md) を参照してください。

2026年10月6日・第2回採点後。**第3〜7回は希少の個人を絞り、第8回で最終回答へ反映する予定です。** 全体MIAも、同じ提出枠で改良・別手法を比較します。

この文書は手順と比較案の説明です。第3回に選ぶ実際のID、追加する外れ人数、提出CSVはまだ作成・確定していません。

## 1. 今回の出発点

| チーム | 分かった人数 | 個人を調べる前の候補 |
|---|---:|---:|
| 6・11・17 | 各1人 | 各11人 |
| 10・16・25 | 各2人 | 各55通りの2人組 |
| その他の16チーム | 0人 | この希少候補の個人探索は不要 |

【第1・2回の公式点数からの条件付き導出】候補11人は、47、76、90、115、169、264、304、383、462、495、675です。誰が正解かはまだ分かっていません。共有条件・提出CSVの前提は[人数の導出](第1回と第2回からの希少MIA人数の導出.md)を参照してください。

## 2. 第3回から変えること

第1・2回は、候補11人を全員同じ高い値にしました。第3回からは**一部だけを選んで高くし、「選んだ側に何人いるか」を調べます。**

説明用に、2人いるチームで仮の候補A〜KからA〜Dの4人を選ぶとします。実際のID選択を示した例ではありません。

| 選んだ4人の中の正解 | 残る候補 | 2人組の数 |
|---|---|---:|
| 0人 | 残り7人から2人 | 21通り |
| 1人 | 選んだ4人から1人、残り7人から1人 | 28通り |
| 2人 | 選んだ4人から2人 | 6通り |

最初の55通りを、1回でいずれかまで減らせます。1人いるチームなら、例えば5人と6人に分け、正解がいる側を残します。

**次の回は、残った候補を分ける別の人選に変えます。** 同じ質問を繰り返す計画ではなく、返った結果に応じて次を決める方法です。

ホワイトボードの「5人＋α」「4人＋β」から先の人選は、[具体例をつないだ説明](../../docs/05_ホワイトボード設定の続き.md)を参照してください。最初の4人に1人いると分かった28組の分岐では、次に「前の4人から1人＋後ろの7人から3人」を選び、12・13・3組へ分けます。6チームの平均から答えを読む設定と、第7回まで絞る例も載せています。

## 3. 提出する値と、点数の読み方

希少24人について、調べる候補と、点数を調整するための既知の外れを `0.4` にし、残りを `0.1` にします。

例えば、2人いるチームで候補4人＋既知の外れ1人の計5人を `0.4` にすると、次の点数になります。【公式コードと計算の照合】

| 選んだ4人の中の正解 | そのチームの希少点数 |
|---|---:|
| 0人 | 0 |
| 1人 | 0.0275 |
| 2人 | 約0.0733333333 |

この**0点は「選んだ4人にはいない」**という意味です。そのチームに正解がいないという意味ではありません。正解2人は選ばなかった7人の中にいます。

## 4. チーム別の点数が返らなくても、どう読むか

本番で読むのは、希少の平均点1つです。各チームに追加する既知の外れの人数を変え、答えごとの平均点を違う値にします。

小さな説明例として、正解が1人ずついるX・Yの2チームだけで平均を取るとします。候補1人を選び、Xには外れ1人、Yには外れ2人を追加します。

| 調べた候補の結果 | Xの点数 | Yの点数 | 2チームの平均 |
|---|---:|---:|---:|
| 両方外れ | 0 | 0 | 0 |
| Xだけ当たり | 0.23 | 0 | 0.115 |
| Yだけ当たり | 0 | 0.115 | 0.0575 |
| 両方当たり | 0.23 | 0.115 | 0.1725 |

【説明用の計算】4つの平均がすべて違うので、平均だけから両チームの答えを読み分けられます。

**今回の本戦では、平均に入るのは6チームです。** 第3回の答えは、1人のチームで0・1人、2人のチームで0・1・2人。各チームを別々に数えた上限は `2×2×2×3×3×3＝216通り` です。この答えの組み合わせと平均点の対応を事前に計算します。平均点1つで任意の設定を区別できるわけではなく、**各回で読み分けられる設定を探して確認する**ことが必要です。

正解がいる6チームは、その回の調査で0点でも平均に含まれます。確定済みのチームの回答を調査用に変える場合も、寄与する点数を計算に入れます。個人特定済みだから平均の分母から外す、という処理はしません。

## 5. 第3〜8回の役割

| 回 | 変えること | 結果から判断すること |
|---|---|---|
| 第3回 | 1人のチームでは例えば5人、2人のチームでは4人を選ぶ | 選んだ側に正解が何人いるか |
| 第4回 | 第3回で残った候補を分ける人選に変える | どの人・2人組を除けるか |
| 第5回 | 残った候補をさらに分ける | 確定したチームと、追加調査が必要なチーム |
| 第6回 | 区別できていない人・2人組を重点的に調べる | 1人または1組に絞れたか |
| 第7回 | 最後に残った違いを調べる | 第8回で確定扱いできる範囲 |
| 第8回 | 調査用の値から、確定した所属を重視する値へ変更する | 最終回答に反映し、全体点も含めて採点を確認する |

【既存の検証に基づく進め方】「5人・4人」は分け方の出発点で、実際に選ぶIDを確定したものではありません。各回は、どの答えが返っても候補をなるべく減らせるように人を選びます。

1チームずつの答えが毎回読める場合、既存の手順では、1人なら最大4回、2人なら最大5回で特定できました。2人の例では **55→28→13→5→2→1通り** と減る経路があります。この例は最大の候補群を順に残した経路で、本戦の実測経過ではありません。

6チームの平均点から毎回答えを区別できることは別に確認が必要です。「5回あれば必ず本戦の全員を特定できる」とは断定しません。

## 6. 各回で行う確認

1. 前回までに残った候補と、その根拠になった原本・提出CSVを固定する。
2. 調べる候補と、追加する既知の外れ人数を決める。外れは少なくとも1人加える。
3. 考えられる答えの平均点を計算し、別の答えが同じ値にならず、小数の誤差でも読み分けられることを確認する。
4. **作成した実CSV**で、チーム列・候補ID・同点人数を数え直し、公式の採点関数と別の計算方法で照合する。
5. 提出後は詳細HTMLの `mia.tpr_rare` を省略せずに使う。1つの答えに一致する場合だけ候補を減らす。
6. 候補・設定・点数・次の判断をその回の記録に保存する。

最も近い点数へ無理に当てはめません。0件一致ならCSV・回番号・桁数・前提を確認し、複数一致なら候補を保留します。残り回数で特定できない人を、確定した人として最終回答に入れません。

探索中の希少点数が下がることはあります。第8回では確定した人を高く、外れを低くする回答へ切り替えるため、途中の点数だけで成否を判断しません。

## 7. 全体MIAはどうするか

第1回の全体点数は `0.03434084434084434`、第2回は `0.010909090909090908`。第1回を比較の基準に残します。【公式結果】

以下は**採用未決定の比較候補**です。新しい提出データを作成する前に、対象・変更点・比較元を決めます。

| 比較候補 | 変えること | 判断したいこと |
|---|---|---|
| Gen-LRAの入力項目を変える | 比較に使う項目を一部加える・外す | 第1回の方法を改良できるか |
| 別の分布モデルを使う | データの分布を比べる計算を変える | 第1・2回と違う弱点を拾えるか |
| 近い人を使う方法を改良する | 距離に使う項目や、近い何人を見るかを変える | 第2回の低下を改善できるか |

模擬データの成績だけで、本戦の優劣を確定しません。チーム別の粗い評価帯から、各チームの最良列が分かったとも扱いません。

希少は24人だけで採点しますが、全体MIAにはその24人も含まれます。全体手法と希少の設定を同時に変えた回では、全体点の増減を1つの変更の効果と断定しません。実CSVで希少の読み分けが保たれることも毎回確認します。

## 計算を確認したい人向け

チームの正解人数を `m`、高くした合計人数を `n`、その中の正解人数を `h` とすると、既知の外れを最低1人加えるこの設計では、

```text
そのチームの希少点数 = (24 − m) × h ÷ [100 × m × (n − h)]
```

です。第1・2回は全候補を高くしたので `h=m`。第3回からは一部だけを選ぶため、`h` が0〜mのどれかを読みます。今回の平均は正解がいる6チームの点数の和を6で割ります。
